# Помощник подготовки routing Skills

Комплект предназначен для обычной Workspace Model Open WebUI **0.13.3**.
Помощник читает конфигурацию выбранного агента, согласует профиль и сохраняет
routing Skill. `execute_code`, терминал, API-ключ администратора и изменение
Router Pipe не требуются.

## Файлы

Готовый комплект: [routing-skill-authoring-agent.zip](../dist/routing-skill-authoring-agent.zip).
Распакуйте его: внутри Tool `routing_skill_authoring.py`, импортируемый
Skill `routing-skill-authoring.zip`, системный промпт и эта инструкция.
Оба ZIP создаются локально командой:

```sh
python3 tools/build_authoring_agent.py
```

## 1. Установить Tool

В OWUI откройте **Workspace → Tools**, создайте новый набор инструментов
с именем **Routing Skill Authoring** и вставьте весь Python-файл
`routing_skill_authoring.py` в редактор кода. Сохраните.
Это **Tool**, его не нужно устанавливать в Admin → Functions.

Набор публикует шесть операций: поиск моделей, чтение конфигурации,
чтение файлов рабочих Skills, чтение существующего routing Skill,
рендер и сохранение. У него нет Valves и секретов для настройки.

## 2. Импортировать Skill

В **Workspace → Skills → Import** выберите `routing-skill-authoring.zip`.
После предварительного просмотра завершите импорт и проверьте активность.
Архив содержит `SKILL.md`, контракт Router, шаблон и переносимый Python-скрипт.
При уже существующем одноимённом Skill используйте штатное обновление,
сохранив его ID и права. Запишите фактический ID импортированного Skill.

## 3. Создать модель помощника

В **Workspace → Models** создайте обычную модель:

| Настройка | Значение |
|---|---|
| Имя | Автор routing Skills |
| Model ID | Например, `routing-skill-author` |
| Базовая модель | Доступная вам LLM с native function calling |
| System Prompt | Полный текст `system-prompt.md` из комплекта ([исходник](templates/routing-author-system-prompt.md)) |
| Tools | Только установленный **Routing Skill Authoring** |
| Skills | Импортированный **routing-skill-authoring** |
| Function Calling | Native |
| Встроенные Skills Tools | Включить чтение Skills и их файлов |
| Code Interpreter / execute_code | Не требуется |
| Терминал, Web Search, прочие Tools | Не требуются |

Если интерфейс не предлагает настройку Function Calling в карточке модели,
выберите Native в расширенных параметрах чата с этой моделью. Штатные
readers нужны для чтения собственного рабочего Skill помощника; чужие
Skills он читает через специализированный `read_agent_skill_file`.

Router Preparation к помощнику не прикрепляйте. Выбирайте его прямо в новом
чате: он работает как отдельная обычная Workspace Model, без Router Pipe.
Его собственная запись в `AGENTS` для этого сценария не нужна.

## 4. Проверить права

Вызывайте помощника под своим OWUI-пользователем. Он получает пользователя
из серверной инъекции и заново загружает его из БД; права владельца модели
помощника и административные токены не подставляются.

- Для изучаемой модели требуется **write**: владение моделью, прямой или
  групповой grant, либо штатный административный обход ACL, если он включён.
  Одного read-доступа недостаточно.
- На рабочие Skills и локальные Tools изучаемого агента нужны собственные
  права чтения. Право записи на модель их автоматически не предоставляет.
  Недоступные ресурсы возвращаются как пробелы обзора.
- Для создания Skill пользователь должен иметь штатное разрешение
  Workspace Skills / импорта Skills. Для обновления нужен write-доступ
  на конкретный Skill. Создание и обновление проходят штатные обработчики
  OWUI, включая проверки, историю и конфликт версий.
- Дайте пользователю доступ к самой модели помощника, его Tool и рабочему
  Skill штатными средствами OWUI. Проще начать с одного владельца всех
  этих объектов, затем при необходимости настроить групповые права.

Помощник не меняет права, модели, `AGENTS` или настройки сервисов.
Новый routing Skill приватен для создавшего его пользователя и активен.
Обновление сохраняет владельца, grants, активность и файлы кроме `SKILL.md`.

## 5. Использовать

Откройте новый чат с помощником:

> Подготовь и сохрани routing Skill для модели `forecast-agent`.
> Изучи её настройки и предложи границы применения и примеры запросов.

Он прочитает настройки и рабочие Skills, предложит позитивные и негативные
примеры и дождётся согласования. После вашего ответа соберёт и сохранит
профиль, вернёт Skill ID, версию и запись для реестра.

Созданный профиль должен быть самодостаточным: отрицательные критерии
описывают только ограничения адресата, без ссылок на других агентов или
назначения альтернативного маршрута. При обновлении помощник должен убрать
старые перекрёстные указания, сохранив существенные границы профиля.

Пример обновления:

> Обнови routing Skill `route-forecast` для модели `forecast-agent`
> с учётом её текущих настроек. Сначала предложи изменения профиля.

## 6. Подключить результат к Router

Владелец публичной Router Workspace Model должен иметь read-доступ к
сохранённому routing Skill. Если это другой пользователь, выдайте ему
этот доступ через карточку Skill. Затем в установленном Filter
Router Preparation добавьте возвращённую пару, сохранив остальные записи:

```python
AGENTS = {
    # существующие записи остаются здесь
    "forecast-agent": "route-forecast",
}
```

Routing Skill не добавляется к рабочим Skills адресата и в `base_skill_ids`.
Если обновляется Skill с тем же ID, существующая запись `AGENTS` сохраняется.
Помощник не читает реестр и не утверждает, что подключение проверено.
Проверьте Router в новом сообщении на позитивном, негативном и неоднозначном
запросах.

## Границы обзора и проверки

Помощник читает сохранённый промпт и настройки выбранной модели, каталоги
её Skills и доступные сохранённые схемы локальных Tools. Он не запускает
рабочие Tools, не читает их Python-код, Valves, ключи и заголовки подключений.
Внешние MCP/OpenAPI-схемы, содержимое Knowledge, наследуемые базовые промпты
и динамические Filters не исследуются. Он должен обозначить эти пробелы и
запросить сведения, если они существенны для профиля. Доступность сервиса
по одним настройкам не считается проверенной.

Автоматические проверки включают отдельный импорт standalone Tool,
генерацию его схем средствами OWUI, права пользователя, создание и обновление
Skills в изолированной БД. Поведение выбранной LLM и установку в вашем
экземпляре OWUI нужно проверить первым диалогом по примеру выше.

Результат локальной проверки 2026-11-13: 105 unit-тестов и 5 отдельных native
тестов помощника прошли. Целевая версия комплекта — 0.13.3, но установленная
локальная сборка OWUI сообщает `0.0.0`. Полная native suite Router в этом
окружении не проходит: обнаружены отсутствующий `mcp.server.mcpserver` и
несовпадения API с существующими тестами. Отдельные проверки помощника
подтверждают перечисленные контракты доступных API, а не полную приёмку
чистой официальной установки OWUI 0.13.3.
