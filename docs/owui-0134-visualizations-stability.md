# Стабильность встроенного Visualizations в Open WebUI 0.13.4

Срез от 19 ноября 2026 года. Open WebUI представил встроенный `render_visualization` 17 ноября, поэтому на момент проверки публичных данных об эксплуатации было мало. В официальном GitHub проверены открытые и закрытые issues, комментарии, связанные PR и история файлов рендера в теге `v0.13.4` и в `dev`. Поиск охватывал `visualization`, `visualizations`, `visualizer`, `render_visualization`, `chart`, `iframe` и `drawing preview`. Отдельный браузерный прогон в этом исследовании не проводился. [Релиз v0.13.4](https://github.com/open-webui/open-webui/releases/tag/v0.13.4)

Эти наблюдения охватывают конкретные сценарии и не дают частоты отказов, проверки нескольких браузеров и провайдеров или гарантии для длинных чатов. Они относятся к другим маршрутам рендера и не дают дополнительных свидетельств о работе `render_visualization` в 0.13.4. ## Что может выглядеть как сбой

- Браузер постепенно рисует HTML/SVG из аргументов вызова. Интерактивный JavaScript, включая инициализацию Chart.js, запускается после завершённого tool output со статусом `accepted` и зависит от разрешения запуска скриптов. Потоковая доставка аргументов влияет на то, насколько рано будет видно превью. [Компонент рендера](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Messages/VisualizationToolCall.svelte) · [Парсер аргументов](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/utils/visualizations/arguments.ts)
- Модель может вернуть неполный JSON при обрыве генерации, HTML свыше 256 КиБ или запросить библиотеку за пределами разрешённого списка. В этих случаях штатный путь финализации виджета не сработает. [Серверная проверка](https://github.com/open-webui/open-webui/blob/v0.13.4/backend/open_webui/tools/visualizations.py#L43-L66) · [Состояния интерфейса](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Messages/VisualizationToolCall.svelte#L280-L319)
- Статус `accepted` означает, что аргументы прошли проверку. Работоспособность сгенерированного JavaScript определяется уже в браузере. Внешние и модульные скрипты запрещены. Ошибка в коде виджета может дать пустой график или неработающий элемент управления после успешного вызова инструмента. [Серверная проверка](https://github.com/open-webui/open-webui/blob/v0.13.4/backend/open_webui/tools/visualizations.py#L43-L66) · [Браузерный рантайм](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/utils/visualizations/runtime.ts#L112-L139)

## Оценка для Lite Handoff Router

Для личного основного чата штатный Visualizations выглядит пригодным для пилота на одной модели. Для просмотра интерактивного графика по Share Preview есть известное ограничение. Для `lite_delegate` и дочерних чатов `delegate_task` upstream-наблюдения не подтверждают стабильность. Текущий роутер собирает список инструментов агента сам и явно добавляет из Builtin Tools только читалки Skills. Перед заменой Inline Visualizer стоит подтвердить появление превью до конца вызова, интерактивность после завершения и повторный рендер сохранённого виджета в обычном handoff и дочернем чате. [Сборка инструментов агента](../src/lite_handoff_router/model_execution.py#L192) · [Браузерная проверка текущего Inline Visualizer](visualizer-browser-evidence.md)
