# Проверка контекста параллельных работников

Изменение: `fix-parallel-worker-task-context`. Версия OWUI: **0.12.5**.

## Проверенный контракт

Работник получает самодостаточный `task` и выбранные вложения. Родительская
переписка не добавляется автоматически. Собственный промпт, рабочие Skills,
Tools и продолжения сохраняются; группой и числом запусков управляет Router.
Обычный и финальный handoff продолжают получать видимую переписку.

## Результат локальной проверки

| Проверка | Результат |
| --- | --- |
| Unit/export | 76 тестов, успешно, без пропусков |
| Native OWUI 0.12.5 | 54 теста, успешно, без пропусков |
| Два задания одной модели | Два настоящих native дочерних чата, по одному поручению и результату |
| Чтение Skill и рабочий Tool | Поручение и собственные exchanges сохраняются во всех трёх генерациях работника |
| Callable refresh | Внешняя история не подменяет контекст работника; обновлённые файлы сохраняются |
| Обычный и финальный handoff | Сохраняются переписка и полные подтверждённые результаты группы, без worker-указания |
| Переполнение контекста работника | Явная ошибка одного задания, без повторения; результат другого сохраняется |

[Обезличенные входы и результаты](parallel-worker-context-validation.json)
содержат поручения, подготовленные сообщения, имена Tools, эффективный контекст
Tool и результаты трёх нативных сценариев. Тестовые IDs нормализованы для
чтения; JSON служит отчётом, а не историей для повторного исполнения.
SHA-256 обеих сборок записаны в том же отчёте.

Проверки запускают собранные самостоятельные Functions через штатные loaders,
native delegate, реальные сохранённые дочерние чаты и streaming Tool loop.
Внутрипроцессный обработчик соединяет native dispatch с экспортированными
Preparation/Pipe. Транспорт генерации заменён детерминированным провайдером.
Это проверка состава контекста и исполнения цепочки; HTTP, браузер и поведение
реальной LLM в другом контуре ей не подтверждаются.

Основные команды (Python-окружение должно содержать `open-webui==0.12.5`):

```sh
python tools/build_functions.py
PYTHONPATH=src python -m unittest discover -s tests -v
python tools/run_native_tests.py --data-root /tmp/lhr-worker-native-check
openspec validate fix-parallel-worker-task-context --strict
git diff --check
```

MCP-тестам требуется возможность открыть локальный порт на `127.0.0.1`.

## Открытая приёмка на реальной модели

Пользователь подтвердил, что рабочая модель находится в другом контуре,
недоступном из этого окружения. Задача **3.3 остаётся открытой**.

В том контуре после установки согласованной пары Functions обновите
сохранённый Router-промпт и routing Skills по
[руководству](router-configuration.md#7-как-проверить-обновление).
Проверьте три сценария:

1. Задайте нужные параметры прогноза, затем попросите: «сделай 2 параллельных
   вызова в этот агент, покажи прогноз ФТП». В `lite_parallel` должны быть два
   элемента одного `agent_id` с самодостаточными `task`. Каждый работник
   выполняет одно поручение, без обещания сделать оба запуска последовательно.
2. Укажите период, идентификатор ФТП и формат ответа в предыдущей реплике.
   Проверьте, что Router перенёс точные значения в каждое поручение и работник
   использовал их без доступа к родительской переписке.
3. Не указывайте необходимый параметр. Router должен уточнить данные или явно
   обозначить ограничение; работник сообщает об обнаруженном недостатке,
   не выдумывая значение.

Сохраните обезличенные аргументы `lite_parallel`, фактические входы моделей
и ответы работников. Отсутствие родительской переписки в отображаемом
дочернем чате само по себе не доказывает состав фактического входа модели.
