# Чаты параллельных сабагентов в боковой панели Open WebUI

Проверка от 19 ноября 2026 года по исходникам последнего стабильного релиза Open WebUI `v0.13.4` и текущему коду Lite Handoff Router. Штатная панель умеет показывать сохранённый чат сабагента рядом с основным. Чтобы открыть его по кнопке из текущего списка выполнений, нужна небольшая доработка фронтенда OWUI. Браузерный прогон роутера на `0.13.4` не проводился. [Релиз](https://github.com/open-webui/open-webui/releases/tag/v0.13.4) · [Реализация вкладок](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Tabs.svelte#L674-L716)

## Что работает штатно

- С `0.13.1` сохранённый чат из левого списка можно перетащить к краю области чата. В `0.13.4` на экранах от 768 CSS-пикселей вкладки можно разместить в панелях с изменяемой шириной. Вкладка использует тот же компонент чата, что и основной экран, и показывает индикатор генерации. [Релиз 0.13.1](https://github.com/open-webui/open-webui/releases/tag/v0.13.1#user-content-added) · [Релиз 0.13.4](https://github.com/open-webui/open-webui/releases/tag/v0.13.4#user-content-added) · [Порог ширины](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Tabs.svelte#L1726-L1733)
- Роутер запускает воркеры через штатный `delegate` и получает ID уже при привязке к заданию. OWUI сохраняет чат с `meta.internal=true`, поэтому обычный список чатов его отфильтровывает и перетащить оттуда нечего. Владелец может открыть чат по ID. [Адаптер роутера](../src/lite_handoff_router/owui_adapter.py#L586) · [Создание чата сабагента](https://github.com/open-webui/open-webui/blob/v0.13.4/backend/open_webui/utils/subagents.py#L587-L594) · [Фильтр списка](https://github.com/open-webui/open-webui/blob/v0.13.4/backend/open_webui/models/chats.py#L1762-L1777) · [Проверка доступа](https://github.com/open-webui/open-webui/blob/v0.13.4/backend/open_webui/models/chats.py#L2049-L2072)
- Текущая ссылка «Открыть выполнение» передаётся как Markdown внутри события `source`. В `0.13.4` обработчик Markdown для `/c/<id>` вызывает `goto`, и основной экран переходит в дочерний чат. Ссылки на источник с абсолютным HTTP(S)-адресом в окне цитаты открываются в отдельной вкладке браузера. `/side` и `/btw` принимают текст начального запроса и создают новую беседу из контекста родителя. [Событие роутера](../src/lite_handoff_router/parallel.py#L187) · [Обработчик ссылки](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Messages/Markdown/MarkdownInlineTokens.svelte#L78-L96) · [Окно цитаты](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Messages/Citations/CitationModal.svelte#L103-L129) · [Команды чата](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Chat.svelte#L4594-L4609)

## Как подключить текущие выполнения

Добавить действие «Открыть сбоку» к ссылке выполнения и передать её `/c/<id>` штатному методу `openPageTab` из `appLayout`. Метод ищет открытую вкладку по ID и использует существующий чат. Для показа рядом сразу можно передать запрос на разделение в существующий `openPanel`, который уже умеет открывать вкладку рядом с основной. Если достаточно отдельной вкладки внутри OWUI, текущему `openPageTab` хватает адреса. Узкое действие на ссылке выполнения позволит оставить обычный переход по всем остальным ссылкам на чаты. [Открытие вкладки](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Tabs.svelte#L658-L716) · [Подключение к контексту](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Tabs.svelte#L1712-L1725) · [Встраивание компонента чата](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Tabs/ChatTab.svelte#L108-L130)

События `source` и `status` доставляют ссылку и прогресс выполнения, но обработчик WebSocket в этой версии не предоставляет команды открытия сохранённого чата в панели. Серверный `GET/POST /api/v1/chats/{id}/view` сохраняет раскладку отдельно для пользователя. Изменение её на сервере подходит только для предварительной настройки будущей загрузки. Уже открытый фронтенд держит свою копию и при следующем сохранении может записать её поверх серверной. [Обработчик событий](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Chat.svelte#L1854-L2080) · [API раскладки](https://github.com/open-webui/open-webui/blob/v0.13.4/backend/open_webui/routers/chats.py#L1421-L1458) · [Загрузка и сохранение в клиенте](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/stores/chatViewStates.ts#L111-L172)

Изолированная проверка `openTabInSplit` в Node.js подтвердила, что первый воркер открывается в отдельной панели рядом с основным чатом, второй добавляется вкладкой в ту же панель, а повторное открытие с тем же ID вкладки возвращает фокус на неё. Проверка запускалась с `node:crypto.randomUUID` вместо импорта `uuid`. [Раскладка вкладок](https://github.com/open-webui/open-webui/blob/v0.13.4/src/lib/components/chat/Tabs/tabs.ts#L181-L192)

При проверке интеграции нужно открыть два выполнения из одного параллельного запуска, пока ответы ещё генерируются, и проверить повторный клик, завершение и отмену. API загрузки чата добавляет данные активных потоков, а сервер направляет события внутреннего чата в комнату пользователя. Текущие нативные тесты проекта закреплены на `0.13.3`.
