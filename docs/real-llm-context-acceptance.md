# Реальная OpenRouter-приёмка: задачи 3.3 и 5.4

2026-11-10, изолированный официальный OWUI 0.13.3, standalone Functions,
native child dispatch и Tool loop. Router и работник используют реальную
`nvidia/nemotron-3.5-lightning:free` через OpenRouter. Все входы синтетические.
Цена завершённого сценария по usage: 0. Ключ не сохранён в репозитории,
OWUI или отчёте; временные файлы ключа удалены после прогона.

Первый пробный запрос Gemma получил upstream 429. Nemotron доступен.

## Фактический результат — не пройдено

Запрошены два параллельных вызова одного агента. Раннее сообщение содержит
FTP-42, даты 2026-11-01–2026-11-30, наблюдения 100/100/100 и формат краткой таблицы.
Реальный Router прочитал Skill, затем выдал один delegate_task. После результата
он выдал второй delegate_task следующей генерацией. Второй запуск отклонён
существующим ограничением одной группы на запрос. Фактически создан один child.

Первый работник выполнил один worker_lookup и вернул один прогноз.
Router затем сделал handoff. Итоговый ответ перечислил два результата с
одним и тем же ID единственного выполнения. На финальном этапе worker_lookup
вызван трижды. Это не удовлетворяет критериям двух независимых запусков,
достоверной итоговой сводки и однократности действий.

Синтетическая метка пользовательской памяти SYNTHETIC-REPORT-ORANGE присутствует
в итоговом ответе. Это лишь частичное положительное наблюдение: источник памяти
создан native hidden_tool_result, retrieval/embeddings не проверялись.

Сценарии нехватки данных, отдельного обычного handoff, A+B и собственного
терминала не выполнены: runner остановился на проваленной проверке числа children.
Обе исходные задачи остаются открытыми. Не заменяем реальную проверку scripted
provider и не меняем production-поведение ради зелёного отчёта.

Входы, поручения, Tool calls и ответы: [JSON evidence](real-llm-context-acceptance.json).
Runner: `tools/real_llm_context_acceptance.py`; ключ задаётся только через
`LHR_OPENROUTER_KEY_FILE`. Runner намеренно завершился assertion failure.


## После исправления

Runtime теперь блокирует handoff после отклонённой дополнительной группы и
сохраняет предыдущие результаты. Тестовый промпт больше не предполагает два
полученных результата; при синтезе он не требует новых worker_lookup.
Runner явно запрашивает parallel_tool_calls и отдельно валидирует уникальные
исполнения и число lookup на каждое исполнение. Это не результат нового live
прогона: исходный неуспешный JSON сохранён, обе реальные приёмки остаются открытыми.
