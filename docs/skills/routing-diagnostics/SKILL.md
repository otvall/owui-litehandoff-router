# Диагностика

Для инцидента получи ID чата и сообщения. Вызови `inspect_routing_turn`
и покажи подтверждённые сведения о кандидатах, чтении, передаче и исходе.
Укажи первый подтверждённый сбой и пробелы. Для текущей конфигурации
используй `inspect_router_catalog` с точным ID Router. Снимок текущего
каталога и свидетельства прошедшего хода датируй отдельно. Если подтверждена
проблема в формулировках профиля, продолжи по `routing-skill-authoring`.

## Группа

Найди фактический ID этого Skill и прочти `references/test-groups.json`
через `read_skill_file`. Дочитай страницы по `next_offset`. Предложи
доступные группы, если оператор ещё не выбрал группу. Прочти первую страницу
`list_shared_routing_catalog` и передай её версию вместе с ID группы в
`resolve_routing_test_group`. При `blocked` покажи отсутствующие или непригодные
профили. При `ready` покажи группу, состав и версию каталога. Передай этот
состав в `routing-skill-review` для группового ревью.

Для стенда подготовь размеченные кейсы и вызови `export_routing_test_job`
с выбранной группой и проверенной версией общего Skill. Для каждого кейса зафиксируй реплики,
допустимый маршрут или самостоятельный ответ и ожидаемый результат.
Скопируй исходный проблемный запрос, если оператор разбирает регрессию.
Передай JSON оператору. Подтверждай фактический прогон по отчёту стенда.

## Настройка групп

Администратор редактирует `references/test-groups.json` в Workspace Skill
диагностики. Ключ объекта — стабильный ID группы, `description` —
описание, `agents` — список точных Model ID из общего каталога.
Одна модель может входить в несколько групп. Замените пример своими ID.
