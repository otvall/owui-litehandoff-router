# agent-task-inspection Specification

## Purpose

Позволить пользователю проверять сохранённое выполнение параллельных заданий в дочерних чатах OWUI, сохраняя чистоту обычной истории и понятную связь с исходным запросом Router.

## Requirements

### Requirement: Parallel tasks use correlated internal chats

Каждая запущенная параллельная задача SHALL иметь отдельный внутренний чат, связанный с основным чатом, исходным сообщением, пользователем и фактическим агентом. Исполнения одного агента SHALL различаться. Существующий финальный handoff SHALL продолжать основной чат без создания нового дочернего чата.

#### Scenario: Two forecasts precede a presentation

- **WHEN** A и B запускаются для одного запроса, после чего выполняется handoff к C
- **THEN** созданы два разных внутренних чата для прогнозов с проверяемой связью с запросом
- **AND** сохранены фактические Model IDs A и B независимо от транспортного ID
- **AND** презентация C появляется в основном чате без третьего дочернего чата

#### Scenario: Same agent has two assignments

- **WHEN** два задания адресованы A
- **THEN** у них разные дочерние чаты и однозначная связь с соответствующими заданиями

### Requirement: Internal execution does not clutter normal history

Дочерние чаты SHALL сохранять штатную внутреннюю отметку и не появляться в обычном списке, поиске или содержимом папок. Отдельная папка SHALL NOT требоваться. Открытие выполнения по ссылке SHALL NOT превращать чат в обычный элемент истории.

#### Scenario: User returns to the normal chat list

- **WHEN** несколько параллельных заданий завершены или открыты для просмотра
- **THEN** их чаты отсутствуют в обычной истории и поиске
- **AND** основной чат Router остаётся доступным обычным способом

### Requirement: Parent chat shows progress for each task

Основной чат SHALL показывать агента и состояние каждой задачи, включая успешное завершение, ошибку, отмену и таймаут. После создания дочернего чата SHALL предоставляться ссылка «Открыть выполнение». Статусы SHALL NOT выдавать начало задачи за завершённый результат.

#### Scenario: One forecast is still running

- **WHEN** A завершён, а B продолжает работу
- **THEN** основной чат различает их состояния
- **AND** C ещё не представлен как запущенный или завершённый
- **AND** ссылки на уже созданные чаты доступны

#### Scenario: Task fails after a tool call

- **WHEN** B получил ошибку после исполнения Tool
- **THEN** основной чат сообщает ошибку и сохраняет доступную ссылку на исполнение B
- **AND** история уже выполненного действия не скрывается за повторным запуском

### Requirement: Execution links remain available after reload

Ссылки на созданные дочерние чаты SHALL сохраняться в результате группы основного чата с принадлежностью агенту и заданию. После перезагрузки SHALL быть возможно открыть существующее исполнение. Если чат не был создан, система SHALL NOT генерировать несуществующую ссылку.

#### Scenario: User reloads a completed parent chat

- **WHEN** пользователь снова открывает основной чат после завершения группы
- **THEN** сохранённые результаты содержат ссылки на исполнения A и B
- **AND** ссылки открывают соответствующие задания, а не последнее исполнение модели

#### Scenario: Validation fails before child creation

- **WHEN** группа отклонена до создания дочерних чатов
- **THEN** отображается ошибка без выдуманных ссылок на выполнение

### Requirement: Execution history opens in the ordinary chat interface

Пользователь со штатным доступом SHALL открывать дочерний чат по ссылке и просматривать сохранённое задание, вызовы Tools, результаты и ответ. Скрытость модели агента в селекторе SHALL NOT препятствовать просмотру. Несохранённые внутренние рассуждения модели не входят в обещанный состав истории.

#### Scenario: Owner opens a hidden agent execution

- **WHEN** владелец нажимает «Открыть выполнение» для скрытого агента A
- **THEN** обычный интерфейс OWUI загружает соответствующий дочерний чат
- **AND** показывает его сохранённую историю, включая несколько последовательных Tools

#### Scenario: Execution is opened during processing

- **WHEN** пользователь открывает созданный чат до завершения задачи
- **THEN** он видит доступную сохранённую историю и состояние выполнения
- **AND** просмотр не запускает повторную задачу или следующий этап основного запроса

### Requirement: Inspection preserves native access checks

Доступ к дочернему чату и обычным файлам SHALL проверяться штатными правами пользователя чата. Права владельца модели на Tools/Skills/MCP SHALL NOT заменять эти проверки или давать ему доступ к данным пользователя. Ссылка SHALL NOT расширять права или включать auth token. При отзыве доступа или удалении native API SHALL отказывать в чтении; для удалённого чата интерфейс SHALL возвращать на главную без уведомления.

#### Scenario: Another user lacks access

- **WHEN** пользователь без штатного права чтения открывает скопированную ссылку
- **THEN** содержимое чата и файлов ему не предоставляется

#### Scenario: User inspects private capabilities in own execution

- **WHEN** пользователь без отдельных grants на Tools и Skills открывает своё сохранённое выполнение разрешённого агента
- **THEN** он видит собственную историю, Tool calls/results и доступные ему файлы
- **AND** просмотр не выдаёт отдельные grants на ресурсы агента

#### Scenario: Model owner lacks access to user data

- **WHEN** владелец модели без штатного права чтения пытается открыть дочерний чат пользователя или скачать его обычный файл
- **THEN** native проверка отклоняет чтение
- **AND** право владельца загружать ресурсы модели не предоставляет доступ к этим данным

#### Scenario: Child chat no longer exists

- **WHEN** сохранённая ссылка указывает на удалённый дочерний чат
- **THEN** native API отказывает в чтении, а интерфейс возвращает на главную без уведомления
- **AND** Router не восстанавливает историю повторным исполнением Tools

### Requirement: Parent and child lifecycle remain native

Удаление основного чата через штатный endpoint с удалением внутренних дочерних чатов SHALL сохранять это поведение. Система SHALL NOT снимать внутреннюю отметку или родительскую связь ради просмотра. Окончание задачи SHALL NOT автоматически удалять её историю до возможности проверки пользователем.

#### Scenario: Completed work remains inspectable

- **WHEN** группа завершена и основной чат сохранён
- **THEN** соответствующие дочерние истории доступны по ссылкам до их штатного удаления

#### Scenario: User deletes the parent through the native endpoint

- **WHEN** пользователь удаляет основной чат через endpoint OWUI с каскадным удалением внутренних чатов
- **THEN** его связанные дочерние чаты также удаляются по штатному механизму
- **AND** работающие дочерние задачи останавливаются
