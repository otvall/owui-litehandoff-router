# conversation-context Specification

## Purpose

Сохранять непрерывный разговор при смене исполнителей, предоставляя Router обзор работы агентов, а каждому агенту — общую переписку и только допустимую собственную служебную историю.

## Requirements

### Requirement: Preserve the canonical conversation

Система SHALL сохранять исходные сообщения и штатную Tool-историю текущего чата. Разные представления контекста SHALL собираться для вызовов моделей без удаления исходных данных ради подготовки конкретного исполнителя.

#### Scenario: Different models receive different views

- **WHEN** Router и A получают разные представления одной истории
- **THEN** исходная история чата остаётся доступна для последующих сообщений
- **AND** подготовка A не уничтожает результаты, которые позднее нужны Router

### Requirement: Shared dialogue follows the selected agent

Агент SHALL получать текущий запрос, предшествующие пользовательские сообщения и видимые итоговые ответы всех исполнителей. Рабочий контекст SHALL сохранять относящиеся к запросу пользовательские файлы и видимые результаты, не копируя чужие системные инструкции.

#### Scenario: User refers to another agent answer

- **WHEN** ранее B ответил пользователю, а новое уточнение Router передал A
- **THEN** A получает текст уточнения и предшествующую видимую переписку, включая итоговый ответ B
- **AND** A не получает системный промпт или рабочие Skills B

#### Scenario: User supplied attachment survives handoff

- **WHEN** исходный запрос содержит поддерживаемый OWUI файл или изображение
- **THEN** контекст выбранного агента сохраняет ссылку или штатное представление этого вложения
- **AND** передача не заменяет исходный запрос только пересказом Router

### Requirement: Router can inspect completed work across the conversation

Router SHALL получать справочное представление завершённых вызовов и результатов Tools из доступной истории всех исполнителей. Представление SHALL указывать исполнителя, инструмент, аргументы и результат; история SHALL NOT предоставлять Router сами инструменты других агентов.

#### Scenario: Relevant data was produced before the previous turn

- **WHEN** пользователь ссылается на результат Tool из более раннего запроса текущего чата
- **THEN** справочный контекст Router включает этот завершённый результат, если он присутствует в исходной истории
- **AND** обзор не ограничивается автоматически только последним запросом

#### Scenario: Historical tool is not a router capability

- **WHEN** справочный контекст содержит результат специализированного Tool A
- **THEN** Router видит полученные данные и автора выполнения
- **AND** этот Tool не появляется в текущем списке вызовов Router из-за своего присутствия в истории

### Requirement: Historical skill instructions do not become active instructions

Справка Router SHALL отмечать загрузку Skill и его ID без полных исторических инструкций. Из завершённых запросов полные результаты Skill readers SHALL исключаться из нативной истории моделей. Текущие загрузки собственных Skills SHALL сохраняться в допустимой Tool-цепочке, не заменяя проверку актуального набора.

#### Scenario: Another agent loaded a working skill

- **WHEN** в завершённом запросе B загрузил Skill через `view_skill`, чтение файла или поиск по файлам
- **THEN** Router получает сведения о загрузке без полного текста инструкций B
- **AND** A не получает служебную загрузку Skill B в собственной Tool-истории

#### Scenario: A current skill read is needed for execution

- **WHEN** A загрузил разрешённый собственный Skill в текущем запросе
- **THEN** результат остаётся доступен A на следующем продолжении
- **AND** при следующем пользовательском сообщении актуальные инструкции подготавливаются заново

#### Scenario: The same agent returns after a skill update

- **WHEN** A выбран в новом пользовательском запросе после изменения ранее прочитанного Skill
- **THEN** полная старая загрузка Skill не восстанавливается из завершённого запроса как нативный Tool result
- **AND** A получает актуальный каталог и при необходимости читает действующие инструкции заново

### Requirement: Agent tool history is scoped by executor and current capabilities

Агент SHALL получать из завершённых запросов только свои однозначно связанные вызовы и результаты Tools, допустимых в его актуальном наборе. Совпадение имени Tool SHALL NOT разрешать историю другого исполнителя. Трасса Router, handoff и чужие Skill-загрузки SHALL исключаться из рабочего контекста агента.

#### Scenario: Two agents use a tool with the same name

- **WHEN** A и B ранее вызывали разные инструменты с одинаковым именем `lookup`
- **THEN** A получает только принадлежащие A допустимые exchanges
- **AND** результаты B не попадают в нативную Tool-историю A

#### Scenario: Agent is selected again

- **WHEN** после нового сообщения Router снова выбирает A
- **THEN** A получает свои допустимые прошлые результаты и общую видимую переписку
- **AND** наличие других исполнителей между запросами A не меняет авторство этих результатов

#### Scenario: Historical tool was detached

- **WHEN** Tool A присутствует в истории, но больше не входит в актуальные возможности A
- **THEN** его нативный exchange исключается из подготовленного контекста A
- **AND** исходный результат сохраняется в истории чата и справочном обзоре Router

### Requirement: Tool exchanges remain structurally valid

Фильтрация SHALL сохранять завершённые пары «вызов — результат» без осиротевших сообщений. При повторении IDs сопоставление SHALL учитывать конкретный запрос и группу вызовов. Неоднозначные exchanges SHALL исключаться из истории агента, сохраняя доступные сведения в справке Router с неизвестным исполнителем.

#### Scenario: Call ids repeat in different user turns

- **WHEN** одинаковый `tool_call_id` встречается в нескольких запросах
- **THEN** результат одного запроса не подставляется к вызову другого
- **AND** фильтрация выполняется для конкретных exchanges

#### Scenario: Result has no unambiguous call

- **WHEN** история содержит осиротевший или противоречивый Tool result
- **THEN** он не передаётся агенту как валидный результат его вызова
- **AND** Router не получает ложного подтверждения автора или handoff

### Requirement: Preserve the current tool continuation

Все валидные вызовы и результаты текущего выбранного исполнителя SHALL сохраняться между его продолжениями. Служебные user-сообщения, созданные OWUI для результата Tool, SHALL NOT считаться новым пользовательским запросом и сбрасывать выбор агента.

#### Scenario: Agent performs multiple sequential tool calls

- **WHEN** A последовательно выполняет два своих Tools
- **THEN** второй и последующие вызовы модели видят валидные exchanges текущей цепочки
- **AND** модель остаётся A до завершения пользовательского запроса

#### Scenario: Tool produces an image represented as a user message

- **WHEN** OWUI добавляет изображение результата Tool в служебное user-сообщение
- **THEN** система сохраняет связь изображения с текущей Tool-цепочкой
- **AND** Router не запускается заново только из-за роли `user` этого сообщения

### Requirement: Tools observe their model effective context

Tools, получающие историю сообщений, SHALL видеть подготовленный контекст текущего исполнителя, включая допустимые изменения его inlet-фильтров. Обновление функций OWUI SHALL NOT подменять эту историю внешним контекстом Router или другого агента.

#### Scenario: Tool callable is refreshed with outer messages

- **WHEN** OWUI обновляет функцию Tool A и передаёт внешнюю историю запроса
- **THEN** Tool A получает историю, подготовленную для A
- **AND** обновлённые пользовательские файлы сохраняются без восстановления чужой истории

### Requirement: Context limits do not silently change conversation meaning

Первая версия SHALL NOT автоматически пересказывать историю, обрезать результаты без уведомления или повторять инструменты для восстановления данных. При превышении доступного контекста SHALL возвращаться понятная ошибка. Сырые результаты другого агента SHALL NOT автоматически превращаться в собственную Tool-историю адресата.

#### Scenario: Context exceeds the provider limit

- **WHEN** подготовленная история не помещается в поддерживаемое окно модели
- **THEN** пользователь получает ошибку ограничения контекста
- **AND** система не скрывает усечение за успешным ответом

#### Scenario: Another agent needs a previously produced artifact

- **WHEN** A требуется результат B, представленный в общем ответе или доступном файле
- **THEN** A использует это общее представление с сохранением штатных прав
- **AND** отсутствующий в нём сырой Tool result B не подставляется автоматически как результат Tool A
