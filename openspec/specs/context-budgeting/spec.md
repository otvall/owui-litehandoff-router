# context-budgeting Specification

## Purpose

Ограничивать рост рабочего контекста Router и агентов управляемым окном результатов и суммаризацией, сохраняя полную историю и явно сообщая о невозможности уложить обязательные данные в бюджет.

## Requirements

### Requirement: Context policy is administrative and opt in

Система SHALL получать политику контекста из административных настроек Router. Поля бюджета и суммаризации SHALL появляться вместе с соответствующими механизмами. По умолчанию ограничения и суммаризация SHALL быть выключены. Клиентские параметры SHALL NOT подменять политику. Работники SHALL наследовать её из подтверждённого серверного состояния родителя.

#### Scenario: Existing installation has no new settings

- **WHEN** установлены новые Functions с прежними Valves
- **THEN** история подготавливается без нового скрытия и пересказа
- **AND** штатное сжатие OWUI по-прежнему должно быть выключено
- **AND** применяется новый формат исторических handoff и системного каталога из conversation-context, без требования включить окно

#### Scenario: Saved Valves contain settings from an earlier build

- **WHEN** сохранённые Valves содержат поля бюджета или суммаризации, для которых в установленной версии нет механизма
- **THEN** фильтр игнорирует эти поля и применяет сохранённый `tool_result_history_limit`

#### Scenario: Administrator opens context settings

- **WHEN** администратор открывает форму Router Preparation
- **THEN** форма показывает ID суммаризатора, общее полное окно, общий процент запуска и лимит сохранённых результатов инструментов
- **AND** старые абсолютные пороги, окна отдельных моделей, пределы входа и настройки резервов игнорируются

#### Scenario: Client attempts to disable a configured limit

- **WHEN** пользователь передал другой N или бюджет в body, metadata либо аргументах задания
- **THEN** действует административная политика
- **AND** два работника одной модели применяют её независимо к своим цепочкам

#### Scenario: Invalid policy is configured

- **WHEN** N отрицателен, бюджет неположителен, резерв исчерпывает бюджет или настроенная модель суммаризации недоступна
- **THEN** подготовка сообщает ошибку настройки до вызова рабочей модели
- **AND** не исправляет значения молча

### Requirement: Each recipient retains its newest ordinary results

Система SHALL сохранять целиком N свежих допустимых рабочих Tool results в каждом представлении, включая текущую цепочку. Router SHALL считать свои результаты и вложенные результаты завершённых handoff общим окном; агент — только допустимые собственные. Оболочка `lite_delegate` SHALL NOT расходовать N. `null` SHALL выключать окно, `0` SHALL скрывать все рабочие результаты. Ошибки SHALL считаться; повторные IDs SHALL различаться по запросу и группе.

#### Scenario: Window advances during the current turn

- **WHEN** при N=2 завершился третий допустимый обычный вызов
- **THEN** следующий запрос содержит полные результаты второго и третьего вызовов и плашку вместо первого
- **AND** исходный первый результат остаётся в чате

#### Scenario: Router uses native history and delegated results

- **WHEN** Router видит рабочие результаты внутри исторических `lite_delegate` и собственные в нативной цепочке
- **THEN** к ним применяется одно окно N; вложенные результаты считаются по отдельности, оболочки передач не считаются
- **AND** агент считает только допустимые собственные exchanges после проверки исполнителя и актуальных возможностей

#### Scenario: Freshness spans several user requests

- **WHEN** при N=2 два последних рабочих результата находятся в старых handoff, затем Router завершает один новый Tool
- **THEN** полными остаются новый результат и самый свежий из двух исторических, более старый получает плашку
- **AND** при двух новых рабочих результатах оба исторических тела скрыты, но сведения о передачах сохраняются

#### Scenario: A delegated agent uses no tools

- **WHEN** агент ответил без рабочих Tools
- **THEN** историческая оболочка передачи содержит пустой `tool_results` и не расходует N
- **AND** сведения о выбранном агенте и его видимый ответ остаются в истории

#### Scenario: A generation contains several calls

- **WHEN** одна генерация содержит четыре допустимых завершённых вызова и N=2
- **THEN** четыре вызова расходуют четыре позиции, а не одну
- **AND** при одинаковой позиции времени порядок определяется исходным порядком вызовов в группе

### Requirement: Hidden results have model only placeholders

За пределами окна содержимое результата SHALL заменяться явной текстовой плашкой только в представлении модели. Вызов, аргументы, связь с результатом и известный статус SHALL сохраняться до суммаризации соответствующего блока. Оригинальные сообщения и UI SHALL NOT заменяться плашками. Скрытое содержимое SHALL NOT оставаться в дублирующих полях того же результата.

#### Scenario: Result contains an HTML document

- **WHEN** текстовый результат за пределами N содержит HTML, продублированный в полях output, files или embeds результата
- **THEN** ни одно из этих представлений старого HTML не попадает в запрос модели вместо плашки
- **AND** пользовательские сообщения и собственные вложения не изменяются; отдельная обработка изображений результатов не требуется в текущем текстовом scope

#### Scenario: Window is increased

- **WHEN** администратор увеличил N перед новым запросом и оригинал входит в расширенное окно
- **THEN** полное содержимое снова доступно без повторного исполнения Tool
- **AND** checkpoint прежней политики не мешает восстановить допустимый результат

#### Scenario: Tool has a large result or its own reader

- **WHEN** обычный Tool вернул большой результат, остающийся внутри N
- **THEN** Router не обрезает отдельный результат и не добавляет общий инструмент его чтения
- **AND** размер выдачи и её последующее чтение остаются ответственностью соответствующего Tool

### Requirement: Required current context remains verbatim

Текущий пользовательский запрос, системные инструкции, допустимые текущие Skills, подтверждённый native-контекст и полный пакет успешной группы для финального агента SHALL сохраняться дословно. Служебные Skill/native exchanges и этот входной пакет SHALL NOT расходовать N или заменяться summary. Набор возможностей и права SHALL NOT расширяться ради сокращения контекста.

#### Scenario: Skill was read before many ordinary tools

- **WHEN** актуальная разрешённая Skill-загрузка текущего исполнителя старше N обычных результатов
- **THEN** действующие инструкции остаются полными
- **AND** старые Skill-загрузки из завершённых запросов не восстанавливаются

#### Scenario: Mandatory context alone exceeds the budget

- **WHEN** текущий вопрос, инструкции, native-контекст или обязательный пакет группы сами превышают бюджет
- **THEN** система возвращает ошибку ограничения
- **AND** не скрывает их и не подменяет кратким пересказом

### Requirement: Budget covers each complete model request

Перед каждым рабочим вызовом система SHALL оценивать весь подготовленный вход, включая инструкции, сообщения, свежие результаты, схемы инструментов, сводку и медиа. Если настроено общее окно, система SHALL применять рассчитанный из него бюджет. Оценочный подсчёт SHALL явно обозначаться. Ошибка переполнения от провайдера SHALL оставаться возможной и явной.

#### Scenario: Router and agents use a shared context window

- **WHEN** запрос переходит от Router к агенту или запускается параллельный работник
- **THEN** применяется то же полное окно с резервом на генерацию из подготовленного запроса
- **AND** продолжение после каждого Tool проверяется повторно

#### Scenario: Filter adds context or tools

- **WHEN** допустимый фильтр увеличил сообщения или набор схем
- **THEN** итоговая проверка учитывает эти изменения перед отправкой
- **AND** `__messages__` исполняемых Tools соответствует окончательному представлению модели

#### Scenario: Tokenizer or multimodal pricing is not exact

- **WHEN** доступен только оценочный подсчёт
- **THEN** диагностика помечает его как оценку и учитывает встроенный запас
- **AND** отказ провайдера по длине не запускает повторные рабочие действия

#### Scenario: Total context window includes a reserve for completion

- **WHEN** администратор задаёт полное окно через `context_window_tokens`
- **THEN** система вычитает резерв под ответ в 1 024 токена или больший лимит генерации из подготовленного запроса
- **AND** система дополнительно вычитает 1 024 токена на погрешность оценки входа

#### Scenario: Tool result pushes a prepared request beyond its budget

- **WHEN** в продолжение после инструмента добавлен результат и подготовленный запрос превышает бюджет
- **THEN** система проверяет новый вход до обращения к модели и при доступном старом префиксе пытается расширить сводку
- **AND** запрос, который по-прежнему превышает бюджет, отклоняется до вызова рабочей модели
- **AND** завершённый инструмент не запускается повторно

### Requirement: Early compaction uses current context and prior input usage

Router и обычный агент SHALL использовать последний фактический замер входа для той же ветки, исполнителя, модели и применённой сводки как сигнал раннего сжатия. К текущей оценке и предыдущему замеру SHALL применяться единый порог от полного окна. Значение порога по умолчанию SHALL составлять 90%.

#### Scenario: Previous usage reaches the shared threshold

- **WHEN** включена общая сводка, последний совместимый замер достигает общего порога и доступен префикс для сжатия
- **THEN** система пытается расширить сводку до отправки запроса, в том числе когда текущая оценка помещается в настроенный бюджет

#### Scenario: Fresh tool result increases the estimated input

- **WHEN** включена общая сводка, задано общее окно и свежий результат поднимает оценку до общего порога
- **THEN** система пытается расширить сводку, даже если предыдущий замер ниже порога или отсутствует
- **AND** после применения сводки система заново оценивает подготовленный вход с текущим результатом

#### Scenario: The conversation has no completed turns or no configured window

- **WHEN** в чате ещё нет завершённых ходов или общее окно не задано
- **THEN** раннее сжатие по проценту не запускается
- **AND** при ошибке переполнения провайдера используется обработка переполнения

### Requirement: Compaction is incremental and structurally safe

Система SHALL сокращать только совместимый префикс целых завершённых пользовательских ходов. Текущий ход, незавершённые вызовы, N свежих полных результатов и обязательный контекст SHALL сохраняться. Историческая пара `lite_delegate` SHALL оставаться неделимой. Бюджет SHALL перепроверяться после применения сводки.

#### Scenario: A prepared request exceeds its budget

- **WHEN** настроенный бюджет получателя превышен и доступен допустимый старый префикс
- **THEN** система пытается расширить общую сводку, сохраняя свежий хвост
- **AND** рабочая генерация начинается только после успешной повторной проверки бюджета

#### Scenario: The active tool chain alone is too large

- **WHEN** текущий ход и защищённые данные не помещаются даже после сокращения допустимых старых ходов
- **THEN** система возвращает ошибку бюджета, сохраняя текущую цепочку инструментов
- **AND** N не уменьшается и выполненные действия не запускаются заново

### Requirement: Shared summary is reusable across the main conversation

Router и обычные агенты SHALL использовать одну общую сводку для совместимого покрытого префикса. Ключ SHALL определяться содержимым общего префикса в пользовательском чате, Router и моделью суммаризатора. Работники SHALL получать только контекст своих поручений. Сводка SHALL оставаться справочными данными без рабочих полномочий.

#### Scenario: Router and agents need the same covered prefix

- **WHEN** Router или агент основного чата создал сводку и следующему получателю доступен тот же префикс
- **THEN** получатель использует общую сводку без пересказа уже покрытых ходов
- **AND** проверка бюджета учитывает полный подготовленный запрос получателя
- **AND** при необходимости более глубокого сокращения расширяется общая сводка на новые допустимые ходы

#### Scenario: The source changes or the branch diverges

- **WHEN** покрытый ход отредактирован, префикс изменён фильтром или запрос идёт по расходящейся ветке
- **THEN** применяются только сводки, покрывающие совместимый неизменённый префикс
- **AND** смена исполнителя сама по себе не требует пересказа

### Requirement: Shared summary uses only common visible history

Вход суммаризатора SHALL включать допустимую общую историю, завершённые обычные вызовы и совместимую предыдущую сводку. Результаты в пределах общего доступа SHALL передаваться ограниченными текстовыми выдержками. Закрытые результаты агентов, инструкции Skills, native-контекст и защищённые пакеты SHALL оставаться вне сводки.

#### Scenario: A completed turn contains media or an Inline Visualizer block

- **WHEN** допустимый старый ход содержит вложение, медиа или исходник Inline Visualizer
- **THEN** ход остаётся кандидатом на сжатие
- **AND** суммаризатор получает видимые текстовые выводы и пометки об артефактах без исходных медиа и кода визуализации
- **AND** после сжатия исторический ход заменяется общей сводкой в запросе модели, а сохранённый чат сохраняет исходный ход

#### Scenario: Hidden result contains a unique marker

- **WHEN** результат скрыт окном истории или доступен только в исходном контексте инструмента
- **THEN** общая сводка получает название инструмента, исполнителя, статус и плашку вместо результата
- **AND** факты из видимых ответов могут быть переданы с указанием автора

#### Scenario: Router has a visible completed tool result

- **WHEN** обычный завершённый вызов подтверждён как вызов Router, ход допустим для сжатия и окно истории оставляет результат доступным
- **THEN** суммаризатор получает описание вызова и ограниченную текстовую выдержку из результата
- **AND** отсечение части результата отмечается, а полный результат сохраняется в чате

#### Scenario: Conversation records a decision and a hypothesis

- **WHEN** видимая переписка содержит решение, дату, идентификатор и неподтверждённую гипотезу
- **THEN** сводка сохраняет существенные точные значения и различие между решением и предположением
- **AND** передаваемая сводка может включать компактный список дат и идентификаторов, извлечённых дословно из покрытых видимых ходов

### Requirement: Summary execution is bounded and isolated

Сводку SHALL создавать явно настроенная доступная модель с отдельным состоянием запроса, без рабочих Tools и маршрутизации. Вход и длительность обновления SHALL ограничиваться. Предел генерации SHALL задаваться параметрами фоновой задачи, модели или провайдера.

#### Scenario: Summary fails or is interrupted

- **WHEN** суммаризатор возвращает ошибку, таймаут, незавершённый ответ, пустой текст или Tool calls либо пользователь останавливает выполнение
- **THEN** результат не сохраняется и Tools не исполняются
- **AND** при ошибке рабочий вызов допускается только в пределах настроенного бюджета, а отмена завершает подготовку

### Requirement: Shared summary preserves chat data and survives reload

Совместимые сводки сохранённого чата SHALL храниться в серверном `chat.meta.lite_shared_summaries`. Временный запрос SHALL использовать локальный кэш. Обновление SHALL сохранять исходные сообщения, файлы, outputs и прочие метаданные. Модель и Tools SHALL получать только применённую сводку, а не серверные записи кэша.

#### Scenario: Server reload or simultaneous update

- **WHEN** сервер перезапущен или сводка сохраняется одновременно с обновлением чата
- **THEN** совместимая запись может использоваться повторно без пересказа
- **AND** запись устаревшего префикса не применяется к изменённой ветке и не перезаписывает чужие данные

### Requirement: Exhaustion is explicit and observable

Если допустимая подготовка не укладывается в бюджет, система SHALL возвращать понятную ошибку без частичного переключения модели, повторного исполнения Tools и скрытого сокращения обязательных данных. Диагностика SHALL показывать оценку до и после, бюджет, число плашек, объём summary и причину отказа без текстов сообщений, результатов и credentials.

#### Scenario: Huge fresh result cannot fit

- **WHEN** один полный свежий результат вместе с обязательным контекстом превышает бюджет
- **THEN** система сообщает ограничение и основные категории затрат
- **AND** не обрезает результат, не экспортирует его автоматически и не повторяет Tool

#### Scenario: Settings are disabled again

- **WHEN** администратор отключил окно и суммаризацию
- **THEN** модель снова получает исходное допустимое представление без применения старых checkpoints
- **AND** исходная история доступна без обратной миграции
