# Proposal

## Why

Router сейчас поддерживает только OWUI 0.12.3 и не запускается на 0.11.1 из-за проверки версии и отличий внутренних API. Нужен дополнительный комплект для 0.11.1 с обычным handoff, локальными и серверными Tools, штатными Skills и терминалом у выбранных агентов, сохранив работающую версию 0.12.3.

## What Changes

- Добавить профиль OWUI **0.11.1** с самостоятельным ответом Router и обычным `lite_delegate` в том же чате. Новое сообщение снова начинает цикл Router.
- Поддержать локальные Workspace Tools, серверные OpenAPI и MCP из текущей конфигурации модели. Сохранить owner ACL отдельно от пользователя исполнения, его UserValves, OAuth/session auth и доступа к обычным файлам.
- Для Skills 0.11.1 использовать штатный текстовый формат и `view_skill`. Файловые Skill readers 0.12.3 не эмулировать и не требовать для запуска 0.11.1.
- Перенести необязательную привязку `meta.lite_handoff.terminal_id` на 0.11.1: default off, только у выбранных агентов, с существующими серверными подключениями и политикой сессий OWUI.
- Собирать отдельные два standalone exports для 0.11.1 из общего ядра с адаптером версии. Сохранить текущие пути, настройки и полный набор возможностей комплекта 0.12.3; каждый комплект проверяет точное соответствие своей версии сервера.
- В профиле 0.11.1 не публиковать и не запускать `lite_parallel` или вложенное делегирование. Перенос параллельных дочерних чатов, отдельная поддержка Inline Visualizer на 0.11.1, файловых Skills, персональных терминалов, provisioning сред и нового транспорта терминальных артефактов не входят в этот change.

## Capabilities

### New Capabilities

Нет: изменение расширяет существующие возможности исполнения Workspace Model и явно определяет их доступность по версии OWUI.

### Modified Capabilities

- `workspace-model-execution`: профиль 0.11.1, соответствующие версии Skills/Tools/терминал, проверка версии и отдельная offline-установка двух Functions.
- `parallel-agent-tasks`: явная недоступность параллельного исполнения в профиле 0.11.1 при сохранении поведения 0.12.3.

## Impact

Основные точки: `owui_adapter.py`, общая подготовка `model_execution.py`, выбор Skill readers, entrypoints, сборщик `tools/build_functions.py`, native runner и acceptance-фикстуры. Новые exports предполагаются в `dist/owui-0.11.1/`; текущий `dist/` остаётся комплектом 0.12.3. Runtime не требует новых зависимостей, патча OWUI, миграции БД или отдельного сервиса оркестрации.

Основа терминальной части — уже реализованный `add-selective-agent-terminals` (18/18). Его specs пока не синхронизированы в основные; этот change не создаёт повторную capability `agent-terminal-access` и не меняет предыдущие артефакты. Политика `model-bound-resource-access` сохраняется в обеих версиях.

Потребуются изолированные native и реальные Tool-loop прогоны на **обеих версиях**, включая серверные Tools/MCP, два пользователя, выборочный терминал, ошибки доступа, Stop и browser inspection обычного handoff. Совместимость 0.11.1 пока исследована по официальному тегу исходников, а не подтверждена исполнением.
