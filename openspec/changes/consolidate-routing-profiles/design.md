# Design

## Context

Router Preparation сейчас строит персональный реестр из встроенного `AGENTS`. Pipe использует этот реестр для манифеста, обоих инструментов передачи и области штатных Skill readers. Проверка reader сегодня различает Skills по ID. Соответственно, общий ID сам по себе не позволяет разделить доступ к отдельным профилям. Целевая версия Open WebUI по-прежнему 0.13.3.

## Goals / Non-Goals

**Goals**

- Хранить реестр и профили в одном версионируемом Workspace Skill, сохраняя ленивое чтение и персональную маршрутизацию.
- Материализовать из одной версии каталога и область чтения, и схемы передачи. Проверять отзыв прав на применимых вызовах.
- Дать администраторам возможность переключить источник и вернуть старый источник без изменений модели или чата.

**Non-Goals**

- Штатные permissions Open WebUI по-прежнему выдаются на весь Workspace Skill. Изоляция отдельных файлов действует в маршрутизационном runtime. Владельцы прямого read/write-доступа к Skill используют его штатные файлы.
- Формат рабочих Skills агентов и внешние сигнатуры `lite_delegate` и `delegate_task` сохраняются.

## Decisions

### Источник маршрутов

В административных Valves Router Preparation появляется `routing_skill_id` с пустым значением по умолчанию. Пустое значение выбирает прежний `AGENTS`. Заполненное значение выбирает общий Skill на весь запрос, включая случай пустого или повреждённого реестра. Явный выбор источника исключает расхождения между опубликованным Skill и оставленным для отката словарём.

```text
routing-profiles/
  SKILL.md
  agents.json
  profiles/
    forecast.md
    visualization.md
```

```json
{
  "forecast-agent": {
    "path": "profiles/forecast.md",
    "description": "Прогнозы по временным рядам"
  }
}
```

`SKILL.md` описывает общие правила без списка моделей. `agents.json` содержит точные Model ID, относительные пути профилей и короткие описания для поиска кандидата. Отдельный файл реестра позволяет проверять схему без разбора Markdown и публиковать оба файла в одной версии. Путь должен совпадать с каноническим путём текстового, непустого Markdown внутри `profiles/`. Один файл принадлежит одному агенту. Повторные ключи JSON делают реестр непригодным, а невалидные поля, отсутствующие файлы и конфликтующие ссылки на путь исключают соответствующие записи.

### Снимок запроса и область чтения

Подготовка получает активный Skill от имени владельца публичной модели Router и загружает реестр и метаданные файлов из одного снимка. Затем, как и сейчас, она отбирает доступные пользователю активные модели и исключает рекурсию в тот же Pipe. Запрос хранит ID версии и отфильтрованные записи. Pipe формирует из них XML и оба `enum`. Недоступность реестра оставляет Router возможность ответить самостоятельно и диагностируется без публикации исходного JSON.

Каталог сохраняет существующие поля и добавляет `path` для записей общего Skill. Router по-прежнему выбирает кандидата в обычной генерации. Инструкции указывают читать конкретный профиль до конца через `read_skill_file`; режим отдельных Skills продолжает использовать `view_skill`. Чтение общего `SKILL.md` не считается прочтением профиля. Общее описание и профили остаются в Skill, а в контекст загружаются только нужные Router файлы.

Readers используют разрешённый набор путей из персонального реестра. Для `view_skill` список строится из разрешённых файлов. Для `grep_skill_files` поиск идёт по разрешённым файлам до вычисления совпадений и счётчиков. Для `read_skill_file` разрешение проверяется перед чтением каждой страницы. Router повторно проверяет доступ к Skill и к модели соответствующего профиля, при этом читает закреплённую версию. Результаты, утратившие допустимый путь до очередного продолжения, исключаются из него. Подготовка и native refresh сохраняют ограничения даже при повторном появлении того же ID в других источниках Skills.

Прочитанный профиль сохраняется как текущий Tool result Router. Для завершённых ходов используется существующее сворачивание результатов Skill readers. Маршрутизационные профили, их служебные пути и исходный реестр исключаются из рабочего контекста агентов и из материала сводки как инструкции.

### Сохранение помощником

Режим общего Skill принимает явный ID папки, согласованный профиль и ожидаемую версию. Помощник использует существующий рендерер для текста профиля, проверяет права записи пользователя чата на модель и Skill, а затем сохраняет профиль и `agents.json` одной штатной операцией обновления Open WebUI. При обновлении сохраняется путь текущего профиля. Для нового профиля путь выбирается в `profiles/` и проверяется на конфликт. Шаблон пути не требует знания внутреннего ID в тексте профиля.

Отдельные записи профилей в общей папке не являются раздельными границами редактирования. Write на общий Skill следует выдавать тем, кто управляет маршрутами. При конфликте версий помощник перечитывает состояние и предлагает согласовать новый результат. Режим отдельного Skill сохраняется для установок на прежнем реестре.

## Risks / Trade-offs

- Ошибка общего реестра может отключить весь каталог. Подготовка выдаёт диагностику, а оператор может явно переключиться обратно на `AGENTS`.
- При частых правках растёт число конфликтов версий. Одна операция с проверкой версии сохраняет целостность профиля и записи. После конфликта нужна повторная проверка.
- Штатный просмотр общего Skill с правами владельца раскрывает список всех файлов. Ограничение требуется до формирования списка и результатов поиска, включая native refresh и продолжения.

## Migration Plan

1. Экспортировать действующие профили и сохранить текущий `AGENTS`, настройки и комплект Router.
2. Собрать общий Skill с `SKILL.md`, `agents.json` и одним файлом на существующий профиль. Перенести точные Model ID и короткие описания действующих Skills. Дать владельцу Router доступ на чтение.
3. Обновить согласованную пару Pipe и Router Preparation и системные инструкции. Задать `routing_skill_id`, затем проверить каталог под пользователями с разным набором моделей, обычную и параллельную передачу.
4. Для отката очистить `routing_skill_id` при сохранённых `AGENTS` и старых Skills. Общий Skill остаётся доступен администраторам для исправления конфигурации.
