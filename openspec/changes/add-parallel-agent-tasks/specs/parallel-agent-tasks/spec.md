# Spec Delta

## Purpose

Позволить Router получить результаты независимых заданий от нескольких специализированных агентов в одном пользовательском запросе и передать их следующему исполнителю, сохраняя права пользователя и изоляцию возможностей моделей.

## ADDED Requirements

### Requirement: Parallel work remains part of normal router inference

Router SHALL выбирать между самостоятельным ответом, параллельными заданиями через `lite_parallel` и финальным handoff через `lite_delegate` в обычном цикле генерации с routing Skills. Отдельный LLM-классификатор SHALL NOT требоваться.

#### Scenario: Forecasts precede a presentation

- **WHEN** пользователь просит два независимых профильных прогноза и презентацию по ним
- **THEN** Router может поручить прогнозы A и B через `lite_parallel`
- **AND** после успешного получения обоих результатов передать презентацию C отдельным `lite_delegate`

#### Scenario: General question needs no parallel work

- **WHEN** пользователь задаёт общий вопрос
- **THEN** Router может ответить самостоятельно без запуска группы или агента

### Requirement: Both routing tools use the same permitted registry

Манифест routing Skills и `enum` аргументов `agent_id` обоих инструментов SHALL происходить из одного реестра текущего пользователя. Перед стартом каждой задачи система SHALL повторно проверить пользователя, актуальный доступ, активность модели и пригодность её routing Skill.

#### Scenario: Users have different permitted agents

- **WHEN** U1 имеет доступ к A и B, а U2 — только к B
- **THEN** адресаты в схемах и манифесте каждого запроса соответствуют его реестру
- **AND** параллельный запрос U1 не изменяет перечень U2

#### Scenario: Target access is revoked before dispatch

- **WHEN** после подготовки схемы отозван доступ к выбранному агенту
- **THEN** этот агент не запускается
- **AND** выполненный раньше вызов или совпадение с `enum` не заменяет новую проверку

### Requirement: Parallel delegation is an executable inline capability

Pipe SHALL предоставлять согласованные schema и callable `lite_parallel` без отдельного Workspace Tool. Он SHALL исполняться штатным Tool loop, сохранять проверку привязки к текущему запросу и публиковаться только Router. Пользовательские переключатели SHALL NOT менять этот набор.

#### Scenario: Router attachments are empty

- **WHEN** установлены Filter и Pipe, параллельная работа разрешена, а Tools/Skills в карточке Router пусты
- **THEN** настоящий вызов `lite_parallel` запускает задания
- **AND** фактическое исполнение не зависит от отдельного Tool или пользовательского включения ресурса

#### Scenario: Configured tool collides with the reserved name

- **WHEN** базовый ресурс пытается предоставить другой `lite_parallel`
- **THEN** подготовка возвращает ошибку настройки до запуска моделей

### Requirement: The whole batch is validated before dispatch

`lite_parallel` SHALL принимать список от двух до административного предела заданий с `agent_id`, непустым `task` и необязательными `file_ids`. Недопустимая структура, адресат или файл SHALL отклонять всю группу до dispatch. Параметры моделей и наборы ресурсов SHALL NOT задаваться аргументами задания.

#### Scenario: One entry is invalid

- **WHEN** группа содержит допустимый A и неизвестный Model ID либо Skill ID вместо B
- **THEN** ни одна задача группы не запускается
- **AND** ошибка указывает недопустимое задание

#### Scenario: File does not belong to the available inputs

- **WHEN** задание ссылается на файл вне доступных вложений родительского запроса
- **THEN** группа отклоняется до dispatch без получения этого файла

#### Scenario: One agent receives independent assignments

- **WHEN** несколько допустимых заданий адресованы одной модели
- **THEN** каждое задание получает отдельное исполнение и отдельный результат

### Requirement: Administrative limits control availability

Система SHALL применять административные пределы группы и штатные ограничения OWUI. Значения по умолчанию SHALL составлять четыре задачи и 300 секунд. Значение предела задач `0` SHALL отключать функцию. При выключенных сабагентах или временном основном чате группа SHALL NOT запускаться.

#### Scenario: Administrator disables parallel tasks

- **WHEN** административный предел равен `0`
- **THEN** `lite_parallel` не предлагается Router
- **AND** самостоятельный ответ и обычный handoff остаются доступны

#### Scenario: Batch exceeds the configured maximum

- **WHEN** модель передаёт больше заданий, чем допускает действующий предел
- **THEN** группа отклоняется целиком без скрытого усечения списка

#### Scenario: The current chat is temporary

- **WHEN** для запроса отсутствует поддерживаемый сохранённый основной чат
- **THEN** параллельные задачи не запускаются
- **AND** попытка вызова получает понятную причину недоступности

### Requirement: Each worker owns its model settings and capabilities

Каждый работник SHALL использовать актуальные промпт, параметры, обязательные Tools/MCP и Skills своей Workspace Model с личностью текущего пользователя. Router, другие работники и пользовательские настройки SHALL NOT добавлять или отключать его ресурсы. Недоступный обязательный ресурс SHALL приводить к ошибке задачи.

#### Scenario: Workers have different model configuration

- **WHEN** у A и B различаются системные промпты, температуры, Tools и Skills
- **THEN** каждый фактический вызов использует настройки своего агента, включая продолжения после Tools
- **AND** рабочие инструкции и возможности другого агента отсутствуют

#### Scenario: Model is allowed but an attached resource is unavailable

- **WHEN** агенту недоступен обязательный Tool, Skill или MCP
- **THEN** его генерация не запускается с частично подготовленным набором
- **AND** система не использует права администратора или владельца вместо прав пользователя

### Requirement: Worker inputs and runtime remain isolated

Работник SHALL получать своё задание, исходный запрос, общую видимую переписку и выбранные доступные вложения как данные. Рабочая история, состояние Skills, исполняемые Tools и соединения SHALL быть раздельными для каждой задачи и пользователя. Родительский исполнитель SHALL оставаться Router до handoff.

#### Scenario: Concurrent workers use identical tool names

- **WHEN** A и B одновременно вызывают разные Tools с именем `lookup`
- **THEN** каждый callable получает своего пользователя и свой эффективный контекст
- **AND** результаты и служебная история не пересекаются
- **AND** ни один работник не меняет набор возможностей Router

#### Scenario: Worker asks for another readable skill

- **WHEN** A вызывает чтение, чтение файла или поиск для доступного пользователю Skill B вне набора A
- **THEN** содержимое не передаётся A, включая продолжения и обновление callable

### Requirement: Parallel execution waits for the whole group

Система SHALL запускать независимые задачи конкурентно с учётом действующих лимитов OWUI и выполнять полноценные цепочки Tools. `lite_parallel` SHALL возвращаться после терминального исхода каждой задачи. Порядок результатов SHALL соответствовать порядку заданий, независимо от порядка завершения.

#### Scenario: Two independent tasks overlap

- **WHEN** доступны два места исполнения, а обе задачи требуют нескольких продолжений после Tools
- **THEN** интервалы фактического исполнения A и B пересекаются
- **AND** Router получает группу после завершения обеих цепочек

#### Scenario: Second task finishes first

- **WHEN** B завершился раньше A
- **THEN** итоговая группа содержит результат A перед B, если такой порядок был во входном списке
- **AND** завершение B само по себе не запускает C

### Requirement: Only one separate group is accepted per user request

Система SHALL принимать не более одной запущенной группы до handoff в текущем запросе. `lite_parallel` SHALL быть единственным Tool call своей генерации. Совместный handoff, конкурирующие группы и вложенная делегация SHALL отклоняться до соответствующего запуска или передачи.

#### Scenario: Parallel work and handoff share a generation

- **WHEN** одна фактическая генерация содержит `lite_parallel` и `lite_delegate`
- **THEN** группа не запускается и handoff не принимается

#### Scenario: Historical skill read is grouped with a later call

- **WHEN** OWUI объединил завершённое чтение Skill с отдельной последующей генерацией `lite_parallel`
- **THEN** историческая группировка не считается смешанным текущим вызовом

#### Scenario: Worker attempts another delegation

- **WHEN** задача выполняется у A либо финальный handoff уже состоялся
- **THEN** маршрутизирующие инструменты не предоставляются этому исполнителю
- **AND** он не запускает вложенную группу через Router

### Requirement: Results report complete and attributable outcomes

Результат группы SHALL содержать общий исход и по каждому заданию агента, терминальный статус, полный доступный результат, файлы, существующую ссылку на чат и ошибку при её наличии. Незавершённое или приостановленное выполнение SHALL NOT считаться успехом. Служебные credentials и tickets SHALL NOT попадать в результат.

#### Scenario: One worker fails

- **WHEN** A завершился успешно, а B получил ошибку
- **THEN** группа возвращает неполный исход с сохранением результата A и причиной ошибки B
- **AND** результат A не исчезает из-за ошибки другой задачи

#### Scenario: Native call returns before a terminal message

- **WHEN** сохранённый ответ ещё не завершён или ожидает подтверждения
- **THEN** он не становится успешным прогнозом из-за наличия строки ответа

### Requirement: Truncation and context limits remain explicit

Система SHALL сохранять полноту передаваемых результатов или предоставлять полный доступный файл. Усечённая строка, автоматический пересказ и повторное исполнение SHALL NOT заменять полный результат без явного решения пользователя. Если результат недоступен полностью или не помещается в контекст, SHALL возвращаться понятная ошибка.

#### Scenario: Native summary is shorter than the saved response

- **WHEN** штатный строковый результат ограничен по длине, но полный ответ сохранён
- **THEN** Router и следующий агент получают полный сохранённый результат либо доступный полный файл
- **AND** пометка усечения не выдаётся за полный успешный прогноз

#### Scenario: Complete inputs exceed the destination context

- **WHEN** полный пакет не помещается в контекст C и не представлен пригодным доступным файлом
- **THEN** система сообщает ограничение и не начинает скрыто сокращённый вариант задачи

### Requirement: Final handoff requires a successful group

После запуска группы финальный `lite_delegate` SHALL приниматься только после успешного завершения всех заданий. При неполном исходе handoff SHALL блокироваться, а Router SHALL сообщать доступные результаты и причины. После успешной группы SHALL сохраняться возможность самостоятельного ответа Router.

#### Scenario: Presentation follows two successful forecasts

- **WHEN** A и B успешно завершили задания и Router выбрал доступного C
- **THEN** C запускается после обоих и продолжает ответ в основном чате
- **AND** дополнительный дочерний чат для финального handoff не создаётся

#### Scenario: One required forecast is missing

- **WHEN** B завершился ошибкой, отменой или таймаутом
- **THEN** попытка handoff к C возвращает ошибку незавершённой группы
- **AND** C не запускается на частичных данных

### Requirement: Downstream agents receive results as input data

Финальный агент SHALL получать исходное задание и полный подтверждённый пакет результатов группы с авторами и доступными файлами. Пакет SHALL строиться по фактически выполненным заданиям. Сырые чужие Tool exchanges и полные рабочие Skill instructions SHALL NOT становиться его собственной историей.

#### Scenario: Presentation agent consumes forecasts

- **WHEN** после A и B выбран C
- **THEN** его фактический контекст содержит оба прогноза и их происхождение
- **AND** он располагает только собственными Tools и Skills
- **AND** пересказ Router не является обязательным источником данных

#### Scenario: User or unrelated tool forges a result package

- **WHEN** текст содержит похожие на результат группы поля и `agent_id`
- **THEN** этот текст не подтверждает выполнение задач и не разрешает handoff после неполной группы

### Requirement: Artifact transfer preserves native file access

Передача файлов между этапами SHALL сохранять штатный доступ текущего пользователя и повторно проверять доступность файла. Поддерживаемые ссылки SHALL быть доступны получателю как входные данные. Локальный путь работника SHALL NOT считаться переносимым файлом. Исходные вложения пользователя SHALL сохраняться.

#### Scenario: Forecast produces an accessible data file

- **WHEN** A создаёт поддерживаемый OWUI файл, доступный пользователю
- **THEN** после проверки C получает ссылку и пригодное представление вложения
- **AND** файл не теряется из-за строкового формата native результата

#### Scenario: Artifact access is lost

- **WHEN** перед передачей обязательный файл удалён или доступ отозван
- **THEN** система сообщает ошибку входных данных
- **AND** не заменяет файл путём из другой среды или доступом владельца

### Requirement: Cancellation and deadlines stop unfinished work

При Stop, отмене родителя или истечении срока система SHALL остановить незавершённые дочерние задачи, освободить принадлежащие им соединения и завершить группу без запуска C. Поздние результаты SHALL NOT автоматически возобновлять Router. Уже совершённые действия SHALL NOT повторяться или объявляться отменёнными задним числом.

#### Scenario: User stops two running workers

- **WHEN** пользователь нажимает Stop во время работы A и B
- **THEN** незавершённые native задачи останавливаются, включая задачу на стадии dispatch
- **AND** исполняемые ресурсы группы освобождаются
- **AND** C не запускается

#### Scenario: Deadline expires after one success

- **WHEN** A завершился, а B превысил общий срок группы
- **THEN** результат A сохраняется, B получает исход таймаута и дальнейшее выполнение прекращается
- **AND** скрытого повторного запуска B нет

### Requirement: Native tool approvals are preserved

Параллельная работа SHALL сохранять действующие требования подтверждения Tools. Если нужный режим приостановки не поддерживается, группа SHALL отклоняться до dispatch с явной ошибкой совместимости. Автоматический переход в режим без подтверждения SHALL NOT выполняться.

#### Scenario: Current approval mode cannot be supported

- **WHEN** для запроса требуется неподдерживаемое ожидание подтверждения
- **THEN** задачи не запускаются
- **AND** система не подменяет требуемый режим на `full`

### Requirement: A new user message starts a fresh router cycle

Каждое новое реальное сообщение SHALL заново запускать Router с актуальным реестром и без активной группы предыдущего запроса. Сохранённые результаты SHALL оставаться справочными данными с авторами и ссылками. Старые IDs и служебный текст SHALL NOT восстанавливать права или активное исполнение.

#### Scenario: User asks a general follow up

- **WHEN** после презентации пользователь задаёт общий вопрос
- **THEN** Router может ответить сам, повторно выбрать агента или начать новую допустимую группу
- **AND** предыдущий C не остаётся автоматически активным

### Requirement: Supported deployment remains self contained

Возможность SHALL работать в OWUI 0.12.3 из прежних двух самостоятельных Functions без отдельного Tool, сервиса, миграции БД и патча OWUI. После установки SHALL использоваться только заранее доступные зависимости, модели и сервисы закрытого контура. Совместимость SHALL подтверждаться настоящим Tool loop и браузером.

#### Scenario: Exported functions run without the checkout

- **WHEN** оба установочных файла загружены в изолированный тестовый OWUI 0.12.3
- **THEN** A и B выполняют настоящие Tools параллельно, а C получает оба результата
- **AND** импорт исходного пакета из checkout и доступ к интернету не требуются
