# Tasks

## 1. Проверка native исполнителя OWUI 0.12.3

Этот этап — обязательный gate до групп 2–6. При необходимости патча OWUI, утечке возможностей или невозможности корректной остановки работу остановить и согласовать пересмотр дизайна; не подменять исполнитель новым движком молча.

- [ ] 1.1 Подготовить изолированную БД OWUI 0.12.3 и детерминированные локальные A/B с разными промптами, температурами, одноимёнными Tools и собственными Skills плюс посторонний доступный Skill; проверить, что тестовая среда не использует рабочую БД и внешний интернет.
- [ ] 1.2 Проверить минимальный мост `subagents.delegate(background=False)` -> публичный Router -> доверенный выбор работника через серверный ticket; подтвердить фактический запуск A/B без Router LLM в дочерних задачах, подмены общего каталога моделей или `CHAT_COMPLETION_HANDLER`.
- [ ] 1.3 Пройти настоящий native Tool loop с двумя продолжениями каждого агента; сохранить интервалы перекрытия A/B и проверки собственных промптов, параметров, контекстов callable и всех трёх ограниченных Skill readers после refresh.
- [ ] 1.4 Проверить получение child chat/message IDs, полного сохранённого результата длиннее native summary и доступного OWUI файла; подтвердить, что незавершённое или приостановленное сообщение не считается успехом.
- [ ] 1.5 Проверить Stop/таймаут во время dispatch и Tool continuation, отсутствие оставшихся native tasks и MCP-сессий; отдельно проверить сохранение режима подтверждения Tools и отказ до dispatch для неподдерживаемого режима без перехода в `full`.
- [ ] 1.6 В браузере открыть действующий и завершённый дочерний чат скрытого агента, проверить Tool-историю и отсутствие чата в списке/поиске; подтвердить сохранение ссылки после Stop и reload штатными событиями без правки frontend.
- [ ] 1.7 Зафиксировать команды, результаты, ограничения и браузерные доказательства gate в `docs/compatibility.md` и `docs/acceptance.md`; продолжать продуктовую интеграцию только при подтверждении выбранного подхода.

- [ ] 2.2 Создавать inline schema и callable `lite_parallel(tasks)` из текущего персонального реестра и публиковать in-place в ранний registry; проверить реальный вызов в native middleware при пустых Tools/Skills карточки Router и `tools: []` клиента.
- [ ] 2.3 Добавить предварительную проверку всей группы, непустых заданий, точных Model IDs и выбранных файлов; тестами подтвердить отсутствие dispatch при одной недопустимой записи, превышении предела и подставленном Skill ID.
- [ ] 2.4 Ограничить функцию сохранёнными чатами и действующими настройками сабагентов, обработать коллизии зарезервированных имён и неподдерживаемый режим подтверждения; проверить явные ошибки и сохранение обычного handoff при отключённой функции.

- [ ] 2.6 Обновить `docs/setup.md` и примеры инструкций Router/routing Skills для выбора между `lite_parallel` и `lite_delegate`; сверить документированный контракт с генерируемыми схемами и административными defaults.

- [ ] 3.4 Запускать задания конкурентно с упорядоченным сбором терминальных исходов и повторной проверкой доступа перед стартом; проверить перекрытие интервалов, обратный порядок завершения, два задания одной модели и отзыв доступа после предварительной проверки.

- [ ] 4.3 Добавлять подтверждённый пакет A/B в эффективный контекст финального агента как данные с авторами; тестами проверить наличие обоих полных результатов у C и отсутствие чужих Tool chains, полных Skill instructions и возможностей.
