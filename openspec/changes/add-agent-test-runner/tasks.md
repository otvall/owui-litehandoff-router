# Tasks

## 1. Стенд и входные данные

- [ ] 1.1 Подготовить воспроизводимый профиль с OWUI 0.13.3, двумя standalone Functions, локальным провайдером и синтетическими моделями, Skills и ролями. Документировать запуск на чистой БД и проверить его через реальный HTTP-запрос обычного пользователя.
- [ ] 1.2 Добавить предварительную сверку идентификатора стенда, версии OWUI, пары Functions и `AGENTS` с профилем. Проверить, что несовпадение сборки или каталога останавливает прогон до отправки реплик.
- [ ] 1.3 Реализовать загрузку и валидацию кейсов, безопасное разрешение фикстур и выбор по ID кейса или агента. Добавить пример каталога и проверки, что дубли, неизвестные роли и отсутствующие файлы отклоняются до генерации.

## 2. Прогон и отчёт

- [ ] 2.1 Переиспользовать штатный HTTP-путь OWUI для независимых чатов и диалогов с историей. Проверить запуск через Router, разрешённый прямой вызов агента тем же пользователем и сценарий с ограниченным доступом.
- [ ] 2.2 Связать трассу генераций с сохранённым output по call IDs. Добавить проверки самостоятельного ответа, handoff, уточнения, A+B, A+A и частичного исхода. Подтвердить кейсами, что текстовое обещание handoff, повтор одного результата и разнесённые по разным генерациям `delegate_task` не засчитываются.
- [ ] 2.3 Добавить проверки рабочего Skill, Tool и результата агента. Включить синтетический набор с профильными и пограничными кейсами и ресурсными проверками. Проверить, что успешный маршрут и провал ресурса отражаются отдельными результатами.
- [ ] 2.4 Вывести покрытие по полному `AGENTS` и персональной доступности. Проверить отдельные записи для скрытой разрешённой модели, недоступной модели, модели без положительного кейса и кейсов вне фильтра запуска.
- [ ] 2.5 Сохранять машиночитаемый отчёт и сводку с режимом, версией профиля и результатом каждой обязательной проверки. Проверить продолжение после независимого сбоя, статусы `blocked` и `needs_review`, ненулевой код для непройденного набора и исключение секретов из свидетельств.
- [ ] 2.6 Добавить явный режим реальных LLM с настройками проверяемого профиля. Документировать запуск и проверить на уровне транспорта, что промпт, рабочие Skills и параметры сохраняются, а недоступность провайдера регистрируется отдельно от решения модели.

Проверить видимый SVG и клик, отсутствие embed работника в родительском сообщении, reload и повторное открытие в другой сессии владельца без новых вызовов Tool и модели. Повторить открытие чужого выполнения под пользователем без доступа.

Проверить независимость маркеров и состояния двух iframe, интерактивность сохранённого основного сообщения, отсутствие внешних запросов в локальном SVG-кейсе и сохранение доказательств при провале. Описать установку браузера и команду прогона.
