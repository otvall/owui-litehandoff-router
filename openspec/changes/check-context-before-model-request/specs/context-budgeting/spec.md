# Spec Delta

## MODIFIED Requirements

### Requirement: Context policy is administrative and opt in

Система SHALL получать политику контекста из административных настроек Router. Поля бюджета и суммаризации SHALL появляться вместе с соответствующими механизмами. По умолчанию ограничения и суммаризация SHALL быть выключены. Клиентские параметры SHALL NOT подменять политику. Работники SHALL наследовать её из подтверждённого серверного состояния родителя.

#### Scenario: Existing installation has no new settings

- **WHEN** установлены новые Functions с прежними Valves
- **THEN** история подготавливается без нового скрытия и пересказа
- **AND** штатное сжатие OWUI по-прежнему должно быть выключено
- **AND** применяется новый формат исторических handoff и системного каталога из conversation-context, без требования включить окно

#### Scenario: Saved Valves contain settings from an earlier build

- **WHEN** сохранённые Valves содержат поля бюджета или суммаризации, для которых в установленной версии нет механизма
- **THEN** фильтр игнорирует эти поля и применяет сохранённый `tool_result_history_limit`

#### Scenario: Administrator opens context settings

- **WHEN** администратор открывает форму Router Preparation
- **THEN** форма показывает ID суммаризатора, общее полное окно, общий процент запуска и лимит сохранённых результатов инструментов
- **AND** старые абсолютные пороги, окна отдельных моделей, пределы входа и настройки резервов игнорируются

#### Scenario: Client attempts to disable a configured limit

- **WHEN** пользователь передал другой N или бюджет в body, metadata либо аргументах задания
- **THEN** действует административная политика
- **AND** два работника одной модели применяют её независимо к своим цепочкам

#### Scenario: Invalid policy is configured

- **WHEN** N отрицателен, бюджет неположителен, резерв исчерпывает бюджет или настроенная модель суммаризации недоступна
- **THEN** подготовка сообщает ошибку настройки до вызова рабочей модели
- **AND** не исправляет значения молча

### Requirement: Budget covers each complete model request

Перед каждым рабочим вызовом система SHALL оценивать весь подготовленный вход, включая инструкции, сообщения, свежие результаты, схемы инструментов, сводку и медиа. Если настроено общее окно, система SHALL применять рассчитанный из него бюджет. Оценочный подсчёт SHALL явно обозначаться. Ошибка переполнения от провайдера SHALL оставаться возможной и явной.

#### Scenario: Router and agents use a shared context window

- **WHEN** запрос переходит от Router к агенту или запускается параллельный работник
- **THEN** применяется то же полное окно с резервом на генерацию из подготовленного запроса
- **AND** продолжение после каждого Tool проверяется повторно

#### Scenario: Filter adds context or tools

- **WHEN** допустимый фильтр увеличил сообщения или набор схем
- **THEN** итоговая проверка учитывает эти изменения перед отправкой
- **AND** `__messages__` исполняемых Tools соответствует окончательному представлению модели

#### Scenario: Tokenizer or multimodal pricing is not exact

- **WHEN** доступен только оценочный подсчёт
- **THEN** диагностика помечает его как оценку и учитывает встроенный запас
- **AND** отказ провайдера по длине не запускает повторные рабочие действия

#### Scenario: Total context window includes a reserve for completion

- **WHEN** администратор задаёт полное окно через `context_window_tokens`
- **THEN** система вычитает резерв под ответ в 1 024 токена или больший лимит генерации из подготовленного запроса
- **AND** система дополнительно вычитает 1 024 токена на погрешность оценки входа

#### Scenario: Tool result pushes a prepared request beyond its budget

- **WHEN** в продолжение после инструмента добавлен результат и подготовленный запрос превышает бюджет
- **THEN** система проверяет новый вход до обращения к модели и при доступном старом префиксе пытается расширить сводку
- **AND** запрос, который по-прежнему превышает бюджет, отклоняется до вызова рабочей модели
- **AND** завершённый инструмент не запускается повторно

## ADDED Requirements

### Requirement: Early compaction uses current context and prior input usage

Router и обычный агент SHALL использовать последний фактический замер входа для той же ветки, исполнителя, модели и применённой сводки как сигнал раннего сжатия. К текущей оценке и предыдущему замеру SHALL применяться единый порог от полного окна. Значение порога по умолчанию SHALL составлять 90%.

#### Scenario: Previous usage reaches the shared threshold

- **WHEN** включена общая сводка, последний совместимый замер достигает общего порога и доступен префикс для сжатия
- **THEN** система пытается расширить сводку до отправки запроса, в том числе когда текущая оценка помещается в настроенный бюджет

#### Scenario: Fresh tool result increases the estimated input

- **WHEN** включена общая сводка, задано общее окно и свежий результат поднимает оценку до общего порога
- **THEN** система пытается расширить сводку, даже если предыдущий замер ниже порога или отсутствует
- **AND** после применения сводки система заново оценивает подготовленный вход с текущим результатом

#### Scenario: The conversation has no completed turns or no configured window

- **WHEN** в чате ещё нет завершённых ходов или общее окно не задано
- **THEN** раннее сжатие по проценту не запускается
- **AND** при ошибке переполнения провайдера используется обработка переполнения
