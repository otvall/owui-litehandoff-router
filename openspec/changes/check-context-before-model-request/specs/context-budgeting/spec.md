# Spec Delta

## MODIFIED Requirements

### Requirement: Budget covers each complete model request

Перед каждым рабочим вызовом система SHALL оценивать весь подготовленный вход, включая инструкции, сообщения, свежие результаты, схемы инструментов, сводку и медиа. Если настроен жёсткий бюджет, система SHALL применять его с учётом переопределения по Workspace Model ID и полного окна. Оценочный подсчёт SHALL явно обозначаться. Ошибка переполнения от провайдера SHALL оставаться возможной и явной.

#### Scenario: Agent has a smaller budget than Router

- **WHEN** контекст помещается в бюджет Router, но не в бюджет выбранного агента
- **THEN** handoff-подготовка применяет бюджет агента и допускаемое сжатие
- **AND** продолжение после каждого Tool проверяется повторно

#### Scenario: Filter adds context or tools

- **WHEN** допустимый фильтр увеличил сообщения или набор схем
- **THEN** итоговая проверка учитывает эти изменения перед отправкой
- **AND** `__messages__` исполняемых Tools соответствует окончательному представлению модели

#### Scenario: Tokenizer or multimodal pricing is not exact

- **WHEN** доступен только оценочный подсчёт
- **THEN** диагностика помечает его как оценку и включает настроенный запас
- **AND** отказ провайдера по длине не запускает повторные рабочие действия

#### Scenario: Total context window includes a reserve for completion

- **WHEN** администратор задаёт полное окно через `context_window_tokens`
- **THEN** система вычитает больший из `context_response_reserve_tokens` и заданного в подготовленном запросе лимита генерации
- **AND** резерв по умолчанию составляет 1 024 токена
- **AND** если одновременно задан предел входа, система берёт меньший из этого предела и остатка полного окна, затем вычитает `context_safety_margin_tokens`
- **AND** при использовании только предела входа из него вычитается только запас безопасности

#### Scenario: Tool result pushes a prepared request beyond its budget

- **WHEN** в продолжение после инструмента добавлен результат и подготовленный запрос превышает бюджет
- **THEN** система проверяет новый вход до обращения к модели и при доступном старом префиксе пытается расширить сводку
- **AND** запрос, который по-прежнему превышает бюджет, отклоняется до вызова рабочей модели
- **AND** завершённый инструмент не запускается повторно

## ADDED Requirements

### Requirement: Early compaction uses current context and prior input usage

Router и обычный агент SHALL использовать последний фактический замер входа для той же ветки, исполнителя, модели и применённой сводки как сигнал раннего сжатия. При отсутствии жёсткого бюджета система SHALL также применять порог получателя к оценке текущего запроса.

#### Scenario: Previous usage exceeds the recipient threshold

- **WHEN** включена общая сводка, последний совместимый замер превышает порог и доступен префикс для сжатия
- **THEN** система пытается расширить сводку до отправки запроса, в том числе когда текущая оценка помещается в настроенный бюджет

#### Scenario: Fresh tool result increases the estimated input

- **WHEN** включена общая сводка, жёсткий бюджет отсутствует и свежий результат поднимает оценку выше порога получателя
- **THEN** система пытается расширить сводку, даже если предыдущий замер ниже порога или отсутствует
- **AND** после применения сводки система заново оценивает подготовленный вход с текущим результатом
