# Proposal

## Why

В OWUI 0.13.3 пользовательская память, каталог Skills и список knowledge поступают как скрытые Tool results. Проверка текущих standalone Functions воспроизводит потерю памяти после обычного и финального handoff: Router превращает служебные результаты в историческую справку, а агент исключает их как exchanges с неизвестным исполнителем.

## What Changes

- Различать подтверждённый служебный контекст OWUI и вызовы Tools, сделанные моделями; сохранить независимый provider audit для handoff и обычных Tools.
- Сохранять актуальную пользовательскую память при обычном handoff и финальном handoff после группы, если настройки пользователя и адресата разрешают её использование.
- Обрабатывать native-каталоги по области доступа: пользовательские knowledge — по правам пользователя и актуальным attachments, Skills — по существующему набору выбранной модели. Каталог родителя не расширяет возможности агента.
- Привязать подтверждение native-контекста к серверному запросу, пользователю, чату и сообщению. Клиентские metadata, сохранённая история и совпадение имени Tool не создают такое подтверждение.
- Сохранить task-only вход параллельного работника: родительские записи и их подтверждения не наследуются; собственный контекст child проверяется отдельно.
- Добавить регрессии для нового формата, подделки происхождения, продолжений, нового сообщения, двух пользователей и A+B/A+A с итоговым handoff; повторить native/HTTP проверки OWUI 0.13.3.

Изменение ограничено совместимостью контекста. Прямой native `model_id`, удаление ticket-механизма, background-режим, боковая панель и исправление live-rendering относятся к следующим changes. Новые RAG/knowledge Tools и перенос существующего Skills-манифеста в другой формат не добавляются.

## Capabilities

### New Capabilities

Нет: уточняются существующие границы контекста и доступа.

### Modified Capabilities

- `conversation-context`: подтверждённый native-контекст текущего запроса сохраняется независимо от авторства вызовов модели; handoff, продолжения и новые запросы имеют явные границы.
- `model-bound-resource-access`: native-контекст учитывает пользователя, настройки адресата и актуальную область ресурсов без расширения grants или использования владельца для чтения пользовательских данных.

## Impact

- Подготовка и проекции: `src/lite_handoff_router/history.py`, `runtime.py`, `model_execution.py`, entrypoint Pipe; адаптация native-данных — через `owui_adapter.py` и при необходимости отдельный внутренний модуль.
- Сохраняются один Filter и один Pipe, штатный Tool loop, `lite_delegate`, синхронная группа `lite_parallel`, owner/actor ACL и терминал из карточки модели.
- Runtime-проверка точной версии и обязательная минимальная версия не вводятся. Существующая информационная metadata версии не меняет смысл.
- Затрагиваются unit/native тесты, самостоятельные exports и документация контекста/совместимости. Дополнительный сервис и патч OWUI не требуются.
- План учитывает завершённый `upgrade-owui-0130-compatibility` и реализованный task-only контракт `fix-parallel-worker-task-context`; их старые основные specs не используются для возврата version guard или родительской истории. Незавершённая реальная LLM-приёмка второго change не закрывается этим планом.
