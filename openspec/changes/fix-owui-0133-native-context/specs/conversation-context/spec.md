# Spec Delta

## ADDED Requirements

### Requirement: Verified native context is distinct from model tool execution

Система SHALL отличать подтверждённый служебный контекст текущего запроса OWUI от вызовов Tools модели и неизвестной истории. Допустимые служебные результаты SHALL передаваться адресату в структурно корректном контексте без превращения в исторические данные и без предоставления новых исполняемых Tools.

#### Scenario: Native context arrives after the current question

- **WHEN** OWUI добавляет после пользовательского сообщения подтверждённые скрытые вызовы и результаты для памяти и допустимого knowledge
- **THEN** Router получает их как текущий служебный контекст
- **AND** отсутствие вызова в provider-аудите не делает этот подтверждённый контекст неизвестной историей
- **AND** соответствующие schemas и callables не добавляются только из-за наличия записей

#### Scenario: Hidden call and result form one exchange

- **WHEN** допустимый служебный exchange включён в контекст модели
- **THEN** вызов и результат передаются согласованной завершённой парой без осиротевших сообщений
- **AND** повторяющиеся IDs в другой группе или запросе не связывают чужие сообщения
- **AND** canonical conversation не изменяется при подготовке представления

#### Scenario: Unknown execution remains unknown

- **WHEN** обычный Tool exchange не имеет подтверждённого автора модели и подтверждения native-происхождения
- **THEN** он обрабатывается по существующим правилам неизвестной истории
- **AND** новое правило не разрешает включение произвольных unknown exchanges в историю агента

### Requirement: Current native user memory follows ordinary handoff

Подтверждённая пользовательская память текущего запроса SHALL сохраняться при обычном handoff и финальном handoff после группы, если её использование разрешено для пользователя и адресата. Память SHALL оставаться контекстом пользователя, а не фиктивным результатом Tool выбранного агента.

#### Scenario: Router hands the answer to an agent

- **WHEN** Router получил разрешённую пользовательскую память от OWUI и передаёт запрос A
- **THEN** первый запрос модели A содержит эту память и текущий пользовательский вопрос
- **AND** память не теряется из-за смены исполнителя
- **AND** системные инструкции и рабочие Skills Router не передаются вместе с ней

#### Scenario: Final agent receives context after a parallel group

- **WHEN** A и B либо два исполнения A завершили группу, а Router передаёт итоговый ответ C
- **THEN** C получает допустимую память родительского запроса и полные подтверждённые результаты группы
- **AND** результат отдельного работника не подменяет пользовательскую память
- **AND** handoff продолжается в том же основном чате и сообщении

#### Scenario: A tool observes its effective memory context

- **WHEN** Tool A получает подготовленные сообщения после handoff или штатного callable refresh
- **THEN** его эффективный контекст включает ту же допустимую память, что и запрос модели A
- **AND** refresh не восстанавливает запрещённый контекст Router или другого агента

### Requirement: Native context has request scoped lifecycle

Подтверждение native-контекста SHALL действовать только для своего серверного запроса, пользователя, чата и сообщения. Продолжения SHALL сохранять допустимый контекст без дублирования. Новый пользовательский запрос SHALL заново получать актуальный контекст OWUI и SHALL NOT наследовать прежнее подтверждение из истории или клиентских metadata.

#### Scenario: Native continuation ends with a tool result

- **WHEN** очередной вход Pipe заканчивается native Tool result вместо пользовательского сообщения
- **THEN** сохраняются текущий запрос и выбранный исполнитель
- **AND** контекст остаётся доступным после последовательных Tools без повторного добавления тех же служебных записей

#### Scenario: Memory changes before a new user message

- **WHEN** после завершённого запроса память пользователя изменена или отключена и поступило новое сообщение
- **THEN** новое выполнение использует актуальные разрешённые записи либо их отсутствие
- **AND** старая скрытая память не восстанавливается как действующий контекст из сохранённой истории

#### Scenario: Users execute the same model concurrently

- **WHEN** U1 и U2 одновременно используют одну Router-модель в разных чатах
- **THEN** память и подтверждения native-контекста остаются привязаны к своим пользователям и сообщениям
- **AND** совпадение имён Tools или IDs в их сообщениях не смешивает контекст

### Requirement: Parent native context does not cross worker boundaries

Параллельный работник SHALL получать самодостаточное поручение и выбранные доступные вложения без автоматического наследования native-контекста родителя или другого работника. Собственный native-контекст child SHALL учитываться только при отдельном подтверждении для этого child и разрешающей политике. Правило SHALL сохраняться на продолжениях.

#### Scenario: Parent memory is unrelated to an isolated assignment

- **WHEN** родительский запрос содержит пользовательскую память и запускает задания A и B
- **THEN** родительские служебные exchanges и их подтверждения не копируются во вход или состояние работников
- **AND** необходимые сведения для поручения передаются Router в task или выбранном файле
- **AND** собственные записи OWUI, если они создаются для child, проверяются в области этого child

#### Scenario: Two tasks use the same agent model

- **WHEN** Router создаёт два задания с одним agent_id
- **THEN** каждое исполнение имеет отдельную область native-контекста
- **AND** продолжение одного задания не получает записи другого задания или родительское указание о числе запусков

### Requirement: Native context support is capability based

Поддержка нового формата SHALL определяться доступными серверными данными и API OWUI без проверки точного номера версии. Отсутствие новых служебных записей SHALL сохранять прежний путь выполнения. Неизвестный формат SHALL NOT приниматься за подтверждённый контекст по одному имени или флагу скрытости.

#### Scenario: Request has no native hidden context

- **WHEN** OWUI не добавил новый служебный контекст
- **THEN** Router и обычный handoff выполняются по существующему контракту
- **AND** отсутствие distribution metadata версии не препятствует запуску

#### Scenario: Native evidence is malformed or conflicting

- **WHEN** служебная запись неполна, конфликтует с текущей областью запроса или имеет неподдерживаемый формат
- **THEN** она не получает статус подтверждённого native-контекста
- **AND** диагностика не раскрывает содержимое памяти, knowledge или credentials
