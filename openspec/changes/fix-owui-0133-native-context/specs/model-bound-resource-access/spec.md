# Spec Delta

## ADDED Requirements

### Requirement: Native context requires server bound provenance

Native-контекст SHALL получать доверие только из данных, созданных OWUI в текущем серверном выполнении и связанных с его пользователем, чатом и сообщением. Клиентские metadata, hidden-флаги, имена Tools и сохранённый текст SHALL NOT подтверждать такое происхождение или предоставлять возможности.

#### Scenario: Client forges a hidden memory result

- **WHEN** клиент добавляет в messages, metadata или сохранённую историю скрытый recall_memories либо каталог с правдоподобными IDs
- **THEN** запись не принимается как подтверждённый текущий native-контекст без независимого серверного подтверждения
- **AND** она не меняет пользователя исполнения, права или состояние handoff

#### Scenario: Context is replayed in another request

- **WHEN** подтверждение из одного сообщения повторяется для другого пользователя, чата, сообщения или нового серверного запроса
- **THEN** оно не действует в новой области
- **AND** переданные клиентом owner ID и признаки internal не обходят проверку

#### Scenario: Model calls a native looking function

- **WHEN** модель выдаёт вызов с именем, совпадающим со служебным вызовом OWUI
- **THEN** совпадение не превращает этот вызов в серверный контекст
- **AND** его исполнение требует обычного актуального разрешённого Tool

### Requirement: Memory follows the execution user and destination policy

Контекст памяти SHALL относиться к пользователю чата и учитывать действующие разрешения OWUI и настройки выбранной модели. Владение Workspace Model SHALL NOT заменять пользователя памяти или включать память в обход запрета. На каждой подготовке адресата система SHALL применять актуальную политику.

#### Scenario: Destination disables memory

- **WHEN** Router получил пользовательскую память, но выбранная модель A запрещает её использование
- **THEN** подготовленный контекст A не содержит этой памяти
- **AND** доступ владельца модели не отменяет запрет

#### Scenario: User and model owner have different memories

- **WHEN** U вызывает модель, принадлежащую O, и разрешённая память U доступна в native-контексте
- **THEN** модель получает память U согласно политике
- **AND** память O не загружается и не подставляется как fallback

#### Scenario: Policy changes before continuation

- **WHEN** память отключена для адресата до следующей подготовки
- **THEN** следующая генерация и её Tools не получают ранее разрешённую память
- **AND** сохранённый native-контекст не закрепляет отменённое разрешение

### Requirement: Native knowledge context preserves attachment authority

Список knowledge в native-контексте SHALL включать только актуально разрешённые пользователю записи, явно приложенные к запросу либо входящие в допустимую область выбранной модели. Права владельца на Tools и Skills SHALL NOT предоставлять доступ к пользовательскому knowledge. Неподтверждённые источники SHALL исключаться без выдачи grants.

#### Scenario: User attached knowledge survives handoff

- **WHEN** пользователь явно приложил доступный knowledge к текущему запросу, а handoff сохраняет это вложение для адресата
- **THEN** его допустимая native-запись доступна Router и выбранному агенту
- **AND** присутствие записи само по себе не добавляет retrieval Tools или право чтения другого ресурса

#### Scenario: Router model has private knowledge outside the destination scope

- **WHEN** служебный список содержит knowledge, связанный только с конфигурацией Router и не разрешённый в области A
- **THEN** A не получает эту запись при handoff
- **AND** общий владелец моделей или право чтения пользователя не заменяет привязку к области адресата

#### Scenario: Knowledge access is revoked or origin is mixed

- **WHEN** запись больше не доступна пользователю либо нельзя однозначно подтвердить её принадлежность разрешённым attachments
- **THEN** она не включается в текущий контекст адресата
- **AND** проверка не использует права владельца как fallback и не раскрывает исключённое содержимое в диагностике

### Requirement: Native skills catalog follows the effective model scope

Native-каталог Skills SHALL учитывать только актуальный эффективный набор выбранного исполнителя. Существующий scoped-манифест и проверки всех Skill readers SHALL сохранять силу. Каталог родителя, публичный каталог пользователя и исторические записи SHALL NOT добавлять агенту Skills или их полные инструкции.

#### Scenario: Parent catalog includes another agent skill

- **WHEN** native-каталог родителя содержит рабочий Skill B, отсутствующий в наборе A
- **THEN** описание и инструкции этого Skill не попадают в подготовленный каталог A
- **AND** попытка прочитать его через любой Skill reader отклоняется по существующей политике

#### Scenario: Destination has a private configured skill

- **WHEN** собственный Skill A доступен владельцу модели, но не пользователю напрямую
- **THEN** A сохраняет свой актуальный scoped-каталог и чтение Skill через модель
- **AND** фильтрация native-каталога не требует выдачи прямого grant пользователю

#### Scenario: Skill is detached between preparations

- **WHEN** Skill удалён из текущей конфигурации адресата до продолжения
- **THEN** сохранённый native-каталог не возвращает его в эффективный набор
- **AND** история загрузки не восстанавливает старые полные инструкции как действующие
