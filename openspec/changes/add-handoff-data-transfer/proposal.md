# Proposal

## Why

Когда пользователь просит дополнить график данными из другого профиля, выбранному агенту может не хватить исходного ряда. Router видит часть результатов предыдущих исполнителей, но при обычном handoff агент получает общую переписку и свою служебную историю.

## What Changes

- Router сможет указать в `lite_delegate` ссылки на конкретные результаты завершённой работы другого агента в текущей ветке. Доступны результаты, явно разрешённые к передаче и видимые при действующем ограничении истории.
- Агент получит выбранные значения и сведения об источнике отдельным входным сообщением перед текущим вопросом. Собственные допустимые вызовы продолжат поступать в штатном формате.
- При отсутствии нужных данных или настроек графика Router сможет использовать доступный общий артефакт, выбрать исходного автора для правки или сообщить, каких данных не хватает. Существующий путь через `delegate_task` остаётся доступен для получения нового ряда.
- Первая версия охватывает текстовые и JSON-результаты подходящих источников. Доступные файлы по-прежнему передаются штатными средствами Open WebUI.

### Modified Capabilities

- `conversation-context` — выбор и передача данных другого агента в модельный контекст с сохранением происхождения и изоляции инструментов.
- `skill-based-handoff` — необязательные ссылки на исторические данные и проверка выбора до запуска агента.

## Impact

Затрагиваются построение истории Router и агента, серверная подготовка и подтверждение `lite_delegate`, настройки Router Preparation, инструкции маршрутизации, standalone-экспорты и проверки на закреплённой версии Open WebUI. Вызов с одним `agent_id` сохраняет прежний контракт. Схема хранения чатов остаётся прежней.
