# Design

## Context

`history.py` уже определяет исполнителя завершённой пары и строит отдельные представления Router и агента. `owui_adapter.py` сверяет итог handoff с сохранённой веткой, но текущая сверка статуса сама по себе не удостоверяет тело отдельного результата. `protocol.py` подтверждает передачу по серверному состоянию и наблюдённому вызову. `parallel.py` доставляет данные завершённой группы служебным сообщением перед текущим вопросом.

## Goals / Non-Goals

**Goals**

- Передавать точные значения с происхождением и сохранять введённый пользователем запрос.
- Опираться на действующий native Tool loop, изоляцию инструментов и ограничения истории.

**Non-Goals**

- Версионирование и автоматическое редактирование HTML-виджетов, извлечение данных из визуального рендера.
- Новый протокол файлов, перенос между чатами, пересказ скрытой истории или автоматическое повторное выполнение инструментов.

## Decisions

### Административное разрешение и сохранённая ветка

Добавить в Router Preparation opt-in список пар «Workspace Model ID источника, функциональное имя Tool». Пустой список оставляет поведение прежним. Настройка означает разрешение передавать текстовое или JSON-тело результата данного инструмента допущенным агентам этого Router. Администратор выбирает инструменты, которые возвращают данные, пригодные для такого обмена, и пересматривает разрешение при замене инструмента под тем же именем. Служебные чтения, native-контекст, управляющие вызовы и известные инструменты рендеринга исключаются независимо от настройки.

Переиспользовать чтение доступной сохранённой ветки в адаптере. Для выдачи ссылки сверять источник с завершённым сообщением и соответствующей однозначной парой в сохранённом `output`. Сопоставление включает сообщение ветки, позицию пары и содержимое результата. Автор определяется по тому же handoff, который использует текущая проекция. Значение для пакета брать из подтверждённой сохранённой записи. Если ветка либо запись недоступна, достоверность недостаточна или входная история отличается от сохранённой, ссылка не выдаётся. Обычная справка Router сама по себе подходит для маршрутизации, а перенос исходного результата требует этой дополнительной проверки.

### Ссылки в эффективной истории Router

Расширить подходящие элементы `tool_results` необязательным `result_ref`. Выдавать его только записям, оставшимся полными после применения действующего окна. Хранить соответствия в серверном состоянии запроса. Повторно использовать ссылку на ту же запись внутри запроса, пока она ещё присутствует в эффективном контексте. На каждой генерации Router обновлять множество доступных ссылок. Если последующие Tool calls вытеснили запись из окна, проверка отклоняет её ссылку.

Принимать `lite_delegate(agent_id, result_refs?)`. Сверять реальный набор аргументов с наблюдением текущей генерации и проверять, что подтверждённая пара вызов–receipt относится к принятому выбору. Использовать существующие проверки адресата и результата параллельной группы. Проверять весь выбор до изменения состояния, убирать дубликаты в порядке первого упоминания и отклонять ссылки на результаты адресата. Хранить значения пакета в состоянии подтверждённой передачи. Серверный receipt связывает подтверждение с этой передачей и не дублирует тела результатов.

### Входной пакет и продолжения

Добавить пакет к подготовленному для агента массиву сообщений перед фактическим пользовательским вопросом. Использовать `role=user` и служебную пометку, что содержимое — данные указанных источников. Собрать данные в структуре `[{agent_id, tool_results: [{tool, status, result}]}]`. Поле `result` сохраняет исходное строковое или структурированное значение. Аргументы вызова, трасса Router и служебные инструкции исключаются из пакета. Собственные разрешённые пары агента по-прежнему формирует `agent_projection`. Исторический `lite_delegate` остаётся в представлении Router.

Определять позицию вставки по текущему реальному пользовательскому ходу с учётом служебных изображений OWUI. На продолжениях строить сообщение из состояния запроса один раз на модельный запрос. Использовать то же эффективное представление для `__messages__` инструментов. Пакет группы `delegate_task` сохраняет свою доставку и проверку файлов. При совместной передаче оба источника располагаются перед исходным вопросом.

### Работа с графиком

Для точного переноса Router выбирает ряд и, при наличии, декларативные настройки графика или использует доступный OWUI-артефакт. При наличии исходного HTML у автора Router может поручить CRM-агенту получить дополнительный ряд через `delegate_task` и передать финальный запрос автору. Инструкции Router описывают, когда требуется полный исходный ряд и как сообщить о недостающих входных данных. Копирование всех прежних результатов добавило бы в каждый запрос нерелевантные данные, а перенос исторического `lite_delegate` в запрос агенту представил бы их как Tool-цепочку.

## Risks / Trade-offs

- Старый сохранённый чат, временный чат или неоднозначная ветка могут не дать подтверждённого источника. В этом случае доступны штатная переписка и обычные вложения.
- Историческая запись может исчезнуть из окна между генерациями Router. Передача отклоняется с указанием недоступной ссылки. Существующие ограничения входа применяются без скрытого усечения выбранных данных.
- Данные могут содержать текст, похожий на инструкции. Пометка отделяет данные от задания на уровне контекста, а полномочия определяются действующим реестром Tools агента.

## Migration Plan

Пересобрать и обновить обе standalone Functions совместно, затем обновить промпт и примеры настройки Router. По умолчанию источники для передачи отсутствуют. Администратор включает только проверенные источники. Для отключения обмена достаточно очистить разрешённый список. Хранимый формат чатов сохраняется.
