# Design

## Context

Мотивация — в proposal.md. В OWUI 0.13.3 builtin `delegate_task` принимает одно задание и вызывает `subagents.delegate`. Middleware специально собирает вызовы с этим именем в `asyncio.gather`, затем связывает каждый результат с исходным Tool call ID. ID внутрь callable не передаётся и там не нужен. Источники: установленный `tools/builtin.py:1687`, `utils/middleware.py:5706–5820`, `utils/subagents.py:279–711`.

Текущий Router предоставляет пакетный `lite_parallel` и собственный `execute_group`. Целевая версия проекта — 0.13.3; исторические упоминания 0.12.5 не расширяют матрицу поддержки. Изменения контекста работников остаются в своей области ответственности.

## Goals / Non-Goals

**Goals:** использовать штатный конкурентный dispatch и привязку результатов, сохранив специализированные модели работников, атомарную проверку и общий lifecycle группы.

**Non-Goals:** собственный координатор запуска, monkey patch OWUI, передача call ID в callable, последовательные волны, вложенная делегация и background mode.

## Decisions

### Специализированный delegate_task

Заменить публичный `lite_parallel` на `delegate_task(agent_id, task, file_ids?)`. Каждый вход запускает ровно своего работника и возвращает его результат. Router намеренно заменяет штатный builtin с этим именем своим inline callable после подготовки ресурсов; другие конфликты имён остаются ошибкой. Сохранить запрет routing Tools у работников. Не перенимать builtin-семантику текущей модели: выбранная Workspace Model определяет настройки и ресурсы.

Сохранение имени `lite_parallel` отклонено: stock middleware исполняет его последовательно. Имя `delegate_task` обеспечивает нативный gather без нового планировщика.

### Штатный loop владеет call IDs

Не добавлять call ID в аргументы или тело результата. OWUI связывает результат coroutine с исходным вызовом. Одинаковые задания остаются независимыми coroutine с отдельными task IDs. Для общего server-owned пакета использовать отдельные внутренние task IDs и исходный порядок назначений; одинаковые назначения занимают отдельные слоты без попытки восстановить native call ID по тексту. Резервирование слота атомарно до await; число запусков ограничено наблюдаемым числом назначений. Неизвестные назначения и лишние входы отклонять. Не заявлять идемпотентность повторного native вызова по недоступному ID.

### Общее состояние без координатора запуска

Группа определяется полной фактической генерацией из аудита: только delegate_task, уникальные непустые IDs, допустимый размер. Общая preflight future проверяет все аргументы, доступы и файлы до запуска любого работника; все callable ждут её. После проверки каждый callable сам исполняет своё назначение. Общий пакет упорядочивается по назначениям, не по завершению.

Сохранить общий терминальный барьер перед возвратом callable и handoff; это совместимо со штатным gather. Последовательный dispatcher не поддерживается и не эмулируется: native contract test обязан подтвердить нужный путь OWUI 0.13.3. Вторую генерацию заданий в одном запросе отклонять.

### Лимиты и lifecycle

Лимит допускает 1, 0 отключает функцию; defaults — 4 задания и 300 секунд. Общая deadline начинается при принятии группы и не перезапускается каждым входом. Stop, отмена родителя и timeout завершают незаконченные задания и освобождают children, tickets и MCP; частичный исход сохраняет успехи и блокирует handoff. Отсутствующий или отменённый участник не должен оставлять терминальный барьер в бесконечном ожидании.

Исходные аргументы аудита проверять до native schema projection, чтобы старый tasks и неизвестные поля не исчезли незаметно. Старый lite_parallel не публиковать.

## Risks / Trade-offs

- Зависимость dispatch от точного имени delegate_task → native contract и экспортная приёмка на OWUI 0.13.3.
- Конфликт со штатным builtin → заменять только известный builtin в Router; тестировать отсутствие fallback и вложенного routing.
- Одинаковые задания → раздельные coroutine, внутренние task IDs и проверка native соответствия outputs двум разным call IDs.
- Preflight и терминальный барьер → тестировать ошибку до dispatch, отмену до входа всех участников и общий timeout без зависаний.
- Устаревшие schema и инструкции → обновить согласованно с fixtures и парой Functions.

## Migration Plan

Обновить inline tool, routing-инструкции, документацию и fixtures; пересобрать две Functions и проверить в изолированной OWUI 0.13.3. Сохранённая история lite_parallel остаётся справочной и не восстанавливает исполнение. Развёртывать согласованную пару; rollback — прежняя пара и её инструкции. Миграция БД не требуется.
