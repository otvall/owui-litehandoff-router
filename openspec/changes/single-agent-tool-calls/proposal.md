# Proposal

## Why

Сейчас один вызов `lite_parallel` скрывает список заданий нескольким агентам. Нужен явный контракт: каждый Tool call назначает ровно одно задание одному агенту, а для четырёх заданий Router выдаёт четыре вызова в одной генерации.

## What Changes

- **BREAKING**: заменить публичный `lite_parallel` на специализированный `delegate_task` и аргумент `tasks` на `agent_id`, `task` и необязательный `file_ids`; старый пакетный формат отклонять.
- Разрешить от одного до административного предела вызовов `delegate_task` одной генерации; считать их одной группой и запускать конкурентно.
- Использовать штатный конкурентный dispatch `delegate_task` OWUI и штатное сопоставление Tool results с call IDs, без собственного координатора запуска.
- Проверять всю наблюдаемую группу до dispatch, возвращать каждому Tool call только его результат и сохранять общий подтверждённый пакет для handoff.
- Сохранить одну группу на пользовательский запрос, общий таймаут, отмену, изоляцию работников и запрет handoff при частичном исходе.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `parallel-agent-tasks`: одно задание на вызов, группа по реальной генерации, конкурентное исполнение и индивидуальные Tool results.

## Impact

Затронуты `parallel.py`, `parallel_state.py`, наблюдение генераций и сопоставление Tool calls, inline schema, административная валидация лимита, routing-инструкции и документация, unit/native tests и acceptance fixtures. Экспорты двух Functions потребуется пересобрать. Целевая версия — текущая OWUI 0.13.3; патч OWUI, новый сервис и отдельный Workspace Tool не требуются. Существующие изменения контекста работников и native-контекста не переопределяются.
