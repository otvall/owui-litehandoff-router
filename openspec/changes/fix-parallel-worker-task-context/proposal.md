# Proposal

## Why

При просьбе сделать два параллельных вызова одного агента работник получает поручение «покажи прогноз ФТП», но трактует исходную просьбу о двух запусках как свою и выполняет работу дважды последовательно. Router должен формировать самодостаточное поручение каждому работнику без автоматической передачи родительской переписки.

## What Changes

- **BREAKING**: прекратить автоматическую передачу исходного запроса и родительской переписки параллельному работнику. Необходимые сведения Router включает в существующий task, вложения выбирает через file_ids.
- Определить содержание поручения: действие, входные данные, точные параметры, ограничения и ожидаемый результат. Организация группы остаётся у Router.
- Сохранить собственные промпт, Tools и Skills работника; добавить системное пояснение его роли. Сохранять поручение и собственную Tool-цепочку между продолжениями.
- Сохранить передачу переписки при обычном lite_delegate, каноническую историю основного чата и полные подтверждённые результаты группы.
- Обновить Router-промпт, шаблон routing Skill и документацию; проверить фактический вход моделей и два запуска одного агента.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `parallel-agent-tasks`: самодостаточные поручения и выбранные вложения вместо автоматической передачи родительской переписки.
- `conversation-context`: разграничение параллельного поручения и обычного handoff; формирование поручения не служит fallback при переполнении контекста.

## Impact

Подготовка дочернего контекста в parallel.py, model_execution.py и Filter, описание lite_parallel, тесты, docs/context.md, docs/router-configuration.md и шаблоны Router-промпта/routing Skill. Аргументы lite_parallel (agent_id, task, file_ids) сохраняются, но task теперь должен содержать весь необходимый текстовый контекст. Новая LLM для пересказа, новые сервисы и миграции БД не нужны. Поддерживается только OWUI 0.12.5.
