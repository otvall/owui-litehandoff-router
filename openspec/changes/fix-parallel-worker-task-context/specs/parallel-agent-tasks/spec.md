# Spec Delta

## MODIFIED Requirements

### Requirement: Worker inputs and runtime remain isolated

Работник SHALL получать самодостаточное поручение Router и выбранные доступные вложения. Родительская переписка, исходный запрос и чужие Tool exchanges SHALL NOT автоматически включаться в его контекст. Рабочая история, состояние Skills, исполняемые Tools и соединения SHALL быть раздельными для каждой задачи и пользователя. Родительский исполнитель SHALL оставаться Router до handoff.

#### Scenario: Concurrent workers use identical tool names

- **WHEN** A и B одновременно вызывают разные Tools с именем `lookup`
- **THEN** каждый callable получает своего пользователя и свой эффективный контекст
- **AND** результаты и служебная история не пересекаются
- **AND** ни один работник не меняет набор возможностей Router

#### Scenario: Worker asks for another readable skill

- **WHEN** A вызывает чтение, чтение файла или поиск для доступного пользователю или владельцу модели Skill B вне набора A
- **THEN** содержимое не передаётся A, включая продолжения и обновление callable

#### Scenario: Parent conversation contains orchestration instructions

- **WHEN** родительская переписка содержит просьбу вызвать двух агентов, а Router назначает работнику отдельное поручение
- **THEN** фактический вход работника содержит поручение без автоматического добавления родительской переписки
- **AND** необходимые сведения передаются Router внутри поручения или выбранными доступными вложениями
- **AND** исходная история основного чата сохраняется

## ADDED Requirements

### Requirement: Router formulates self-contained worker assignments

Router SHALL формировать в task действие, необходимые входные данные, ограничения и ожидаемый результат каждого задания. Значимые даты, значения и идентификаторы SHALL сохраняться точно; необходимые полные документы SHALL передаваться через доступные вложения. Инструкции об организации группы SHALL оставаться у Router. Отсутствующие необходимые данные SHALL явно обозначаться без выдуманных значений и предположения о доступе работника к переписке.

#### Scenario: Assignment depends on earlier facts

- **WHEN** ранее пользователь указал период прогноза, идентификатор ФТП и формат ответа
- **THEN** Router включает соответствующие точные значения и ограничения в task
- **AND** поручение понятно без доступа к родительской переписке

#### Scenario: Assignment needs an original document

- **WHEN** для выполнения нужен полный документ из доступных входных вложений
- **THEN** Router указывает его в file_ids и объясняет назначение в task
- **AND** файл передаётся со штатной проверкой доступа без замены необходимого содержания приблизительным пересказом

#### Scenario: Required input is missing

- **WHEN** работнику недостаёт обязательных данных для выполнения поручения
- **THEN** он явно сообщает, каких данных не хватает
- **AND** не выдумывает их и не заявляет о чтении недоступной родительской переписки

### Requirement: Each worker executes only its assignment

Работник SHALL получать явное указание роли исполнителя отдельного поручения. Организация группы и число запусков SHALL оставаться ответственностью Router. Назначение, собственные инструкции и допустимая Tool-цепочка SHALL сохраняться при подготовке модели и продолжениях. Работник SHALL NOT получать инструменты оркестрации или повторять поручение ради выполнения родительской просьбы о количестве запусков.

#### Scenario: User requests two parallel calls to the same agent

- **WHEN** пользователь просит два параллельных вызова одного агента, а Router создаёт два задания «покажи прогноз ФТП» с необходимыми параметрами
- **THEN** запускаются два независимых исполнения этого агента, каждое выполняет своё поручение один раз
- **AND** ни одно не выполняет прогноз дважды последовательно из-за родительской просьбы
- **AND** отсутствие инструмента параллельности не препятствует выполнению самого поручения

#### Scenario: Worker continues after reading a Skill or calling a Tool

- **WHEN** работник прочитал свой Skill или получил результат своего Tool
- **THEN** следующий вызов модели сохраняет поручение, пояснение роли и допустимую собственную Tool-цепочку
- **AND** родительская переписка и чужие Tool exchanges не добавляются при продолжении

#### Scenario: Different workers receive different inputs

- **WHEN** Router назначает A анализ продаж и B анализ расходов с разными входными данными
- **THEN** каждый получает своё самодостаточное поручение и выбранные для него вложения
- **AND** поручение другого работника не появляется в его контексте автоматически
