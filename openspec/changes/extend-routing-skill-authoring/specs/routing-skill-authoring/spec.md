# Spec Delta

## ADDED Requirements

### Requirement: Target agent consultation

Помощник SHALL задавать вопрос выбранной Workspace Model по точному Model ID от имени пользователя чата. Для вызова SHALL проверяться штатные права вызова и записи на модель. Ответ SHALL обозначаться как сведения от адресата; проверка внешних сервисов в консультацию не входит.

#### Scenario: Author asks a writable agent about its scope

- **WHEN** пользователь может запускать и редактировать выбранную Workspace Model
- **AND** помощник задаёт адресату вопрос о его задачах, ограничениях или результате
- **THEN** адресат получает один вопрос с собственным системным промптом в изолированном вызове
- **AND** вызов не передаёт историю, файлы и инструменты текущего чата, не запускает рабочие инструменты адресата и не создаёт дочерний чат
- **AND** результат идентифицирует адресата и возвращает его текстовый ответ

#### Scenario: Consultation cannot be performed

- **WHEN** доступ отозван, адресат несовместим с изолированным вызовом или генерация завершилась ошибкой либо тайм-аутом
- **THEN** помощник получает понятный отказ или статус недоступности
- **AND** при существенном пробеле оставляет черновик до уточнения

### Requirement: Versioned read access to the shared routing catalog

Инструменты автора SHALL предоставлять постраничное чтение записей `agents.json` и текстов зарегистрированных профилей явно выбранного общего Skill. Чтение SHALL проверять штатный доступ пользователя к Skill на каждой странице. Страницы одной проверки SHALL относиться к одной версии.

#### Scenario: Author reads the catalog without Skill write access

- **WHEN** пользователь имеет штатный read-доступ к общему Skill
- **THEN** помощник получает точные Model ID, описания, пути, идентификатор версии и данные для продолжения чтения
- **AND** может дочитать профиль по зарегистрированному Model ID, включая профили моделей без write-доступа у этого пользователя
- **AND** этот доступ не даёт прав на конфигурацию моделей или публикацию в Skill

#### Scenario: Catalog changes during review

- **WHEN** следующая страница запрошена для версии, которая перестала быть текущей
- **THEN** инструмент сообщает об изменении версии, и помощник начинает ревью по актуальному каталогу
- **AND** если в каталоге есть повреждённые или недоступные записи, помощник указывает непроверенные части и не объявляет ревью полным

### Requirement: Routing profile review before publication

Комплект автора SHALL включать `routing-skill-review`. Для общей папки помощник SHALL проверять черновик перед согласованием, сопоставляя критерии, исключения, описания и примеры с действующими профилями выбранного каталога.

#### Scenario: Draft contains ambiguous or contradictory routing criteria

- **WHEN** один запрос подходит черновику и соседнему профилю без правила различения, либо критерии и примеры самого черновика дают несовместимые ответы
- **THEN** помощник показывает спорный запрос, конфликтующие пункты и конкретную предлагаемую правку
- **AND** существенная неоднозначность, требующая решения автора, оставляет профиль черновиком до согласования
- **AND** намеренное пересечение с ясным правилом выбора отмечается без требования его устранить

#### Scenario: Existing profile is being updated

- **WHEN** черновик заменяет профиль уже зарегистрированного Model ID
- **THEN** при сравнении с соседями помощник подставляет черновик вместо прежнего профиля этого ID

### Requirement: Publish a profile reviewed against the current catalog

Когда пользователь поручил публикацию в общий Skill и согласовал профиль, помощник SHALL самостоятельно сохранить профиль и его запись в `agents.json` штатной совместной операцией. Версия при сохранении SHALL совпадать с версией, по которой прошло ревью.

#### Scenario: Author publishes an agreed profile

- **WHEN** пользователь имеет право записи на модель и общий Skill, а проверенная версия ещё актуальна
- **THEN** помощник публикует файл профиля и запись по точному Model ID одной версией Skill
- **AND** возвращает Skill ID, Model ID, путь и версию
- **AND** остальные записи и файлы сохраняются

#### Scenario: Catalog changed after review

- **WHEN** редактор успел опубликовать новую версию после ревью
- **THEN** попытка сохранения отклоняется без изменения файла и записи
- **AND** помощник перечитывает каталог и повторяет ревью, а существенные изменения профиля снова согласует с автором
