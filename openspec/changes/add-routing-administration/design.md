# Design

## Context

Обычная Workspace Model автора уже использует общий рендерер для сервера и переносимого скрипта. `save_shared_routing_profile` формирует две операции записи с проверкой версии. Правило `route-<model-slug>` сейчас описано в рабочем Skill, а рендерер проверяет общий kebab-case. Router строит реестр в состоянии запроса, наблюдает вызовы и использует их при передаче. Доступная история чата не гарантирует полного снимка прошедшего хода. См. [предложение](proposal.md).

## Goals / Non-Goals

**Goals**

- Свести предпросмотр и публикацию к одной подготовке изменений, совместимой с действующими ссылками.
- Дать администратору текущий каталог, проверяемый разбор хода и повторяемый тест по выбранной группе.

**Non-Goals**

- Автоматическое изменение настроек рабочих моделей, разрешений и правил выбора Router.
- Массовое переименование опубликованных IDs и путей, запуск произвольных инструментов адресата из чата автора.

## Decisions

### Каноническое имя и точный предпросмотр

Вынести вычисление и проверку имени из инструкций модели в общий код создания. Сохранить действующее правило нормализации: латиница в нижнем регистре, последовательности вне `[a-z0-9]` заменяются дефисом, крайние дефисы удаляются. При пустом результате использовать согласованный ASCII-slug. При совпадении с занятым именем проверить последовательные варианты с суффиксом `-2`, `-3` и далее, оставляя место для суффикса в пределах 64 символов. При обновлении сохранить ранее принятое каноническое имя, если оно по-прежнему соответствует соглашению и принадлежит этой записи. Проверять занятые IDs, имена и пути в выбранном режиме хранения.

Новое имя используется для YAML `name`, имени карточки отдельного Skill и нового ID или имени файла профиля. Точный Model ID остаётся ключом в `agents.json`, а видимое имя адресата остаётся заголовком профиля. При правке старого профиля нормализовать имя в содержимом и карточке, сохраняя опубликованный ID или путь. Например, обновление `profiles/forecast.md` может выставить `name: route-forecast-agent` и оставить ссылку на `profiles/forecast.md`.

Добавить `preview_routing_change` в существующий Tool. Предпросмотр и запись используют одну подготовку рендера, имени, пути и записи в `agents.json`. Сохранение повторяет проверку прав, коллизий и ожидаемой версии. При отличии от согласованного предпросмотра нужен новый предпросмотр. Обновить интерфейс Tool и переносимый скрипт там, где требуется передать или проверить каноническое имя. Сверить `docs/templates/routing-skill/SKILL.md` с новым контрактом и обновить при необходимости. Текущий набор разделов достаточен для согласованного профиля. Нужна одна каноническая версия шаблона, которую использует и сборка.

Расчёт имени только в промпте сохранял бы возможность расхождения между диалогом и записью. Массовая смена ID и путей потребовала бы миграции внешних ссылок. Нормализация при создании и обновлении обеспечивает единый результат для новых записей и безопасно приводит имена редактируемых профилей к формату.

### Промпт и рабочие Skills

Обновить `docs/templates/routing-author-system-prompt.md`: определить намерение, выбрать сценарий, использовать точные идентификаторы и версию, показать доказательства и расхождения, согласовать примеры и публиковать по поручению. `routing-skill-authoring` описывает создание и редактирование, `routing-skill-review` проверяет конкретный черновик, группу либо каталог, `routing-diagnostics` описывает разбор инцидента и подготовку прогона. Консультация `ask_agent` из базового изменения остаётся доступной при содержательном пробеле. Разделить наблюдения запуска, сохранённые настройки и ответ адресата.

### Текущий каталог и трасса хода

Добавить административные readers каталога и хода. Каталог строить через тот же механизм обнаружения, который использует Router Preparation, с фактически настроенным источником и проверкой допусков. Не принимать произвольный список как фактическую конфигурацию Router. Для исторической диагностики привязать компактную трассу к чату и сообщению. Использовать события подготовки реестра, успешного чтения, инструментов передачи и фактического исхода. Сохранять идентификаторы, версии и статусы по мере появления подтверждённых данных, включая доступные сведения о прерванных ходах. Исключить исходные промпты, вложения, секреты и произвольные аргументы Tools. Применять серверную проверку роли и штатный доступ к чату, сообщению и дочерним задачам. Удаление чата должно удалять или делать недоступными связанные сведения.

Для старых ходов извлекать подтверждённые события из сохранённой истории, с пометками о пробелах. Текущий каталог даёт отдельный снимок для проверки текущей конфигурации. Пояснения LLM о мотивации выбора могут использоваться как гипотезы. Доказательства выбора и выполнения берутся из событий.

### Группы и стенд

Хранить операторские группы только в `routing-diagnostics/references/test-groups.json`. Структура сопоставляет ID группы, краткое описание и массив точных Model ID. Администратор редактирует данные в скилле диагностики. Агент читает файл штатным reader, выбирает группу по запросу или предлагает список, затем разрешает участники по тому же снимку `agents.json`. Групповые правила учат сообщать о неизвестных ID и неполном покрытии. Публикация профиля не меняет состав групп.

Передавать тест-раннеру разрешённый состав, версию исходного каталога, идентификатор группы и размеченные кейсы с допустимыми результатами. Зафиксировать снимок состава сразу при подготовке теста. Адаптировать проверку конфигурации стенда из `add-agent-test-runner` для общего Skill: сверить исходный снимок, затем использовать его копию с маршрутизационными записями только выбранной группы. Предусмотреть экспорт задания из чата автора и запуск существующим CLI на стенде. Отчёт можно вернуть в тот же рабочий процесс для разбора. У тестового прогона есть отдельный результат от ревью текста. Для регрессии рабочего Router можно дополнительно прогнать кейс на полном снимке каталога.

## Risks / Trade-offs

- Группа может ссылаться на устаревший состав. Сверка снимка и точных Model ID даёт явный отказ до исполнения.
- Полный исторический обзор возможен для ходов с достаточной трассой. Для остальных инструменты показывают доступные события и пробелы.
- Регрессия за пределами группы видна при прогоне по полному каталогу. Отчёт фиксирует границы каждого прогона.

## Migration Plan

Применить `extend-routing-skill-authoring`, затем обновить комплект автора с сохранением ID установленных Tools и Skills. Прикрепить `routing-diagnostics` и заполнить группы в его рабочем файле. Развернуть изменённую пару Router и Preparation для новых трасс. Поддержку группового исполнения интегрировать с `add-agent-test-runner`. Опубликованные маршруты продолжают разрешаться по прежним ID и путям. При возврате предыдущей сборки эти ссылки остаются пригодными.
