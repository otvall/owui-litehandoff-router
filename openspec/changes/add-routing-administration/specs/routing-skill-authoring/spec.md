# Spec Delta

## ADDED Requirements

### Requirement: Canonical routing Skill names

Предпросмотр, рендер и сохранение SHALL применять единый формат имени `route-<model-slug>`, полученный из точного Model ID. Новые файлы профилей и IDs отдельных Skills SHALL использовать это имя. При обновлении имя профиля SHALL приводиться к формату с сохранением уже опубликованных ссылок.

#### Scenario: Author creates a routing Skill

- **WHEN** точный Model ID равен `Forecast_Agent` и имя свободно
- **THEN** заголовок карточки отдельного Skill и YAML `name` используют `route-forecast-agent`
- **AND** новый отдельный Skill получает ID `route-forecast-agent`, а новый профиль в общей папке получает путь `profiles/route-forecast-agent.md`
- **AND** `agents.json` сохраняет точный ключ `Forecast_Agent`, а заголовок Markdown использует читаемое имя агента

#### Scenario: Normalized name conflicts with another route

- **WHEN** Model IDs дают одинаковый slug или рассчитанное имя занято другим профилем
- **THEN** автор видит свободный вариант с числовым суффиксом и соблюдением предела в 64 символа
- **AND** занятую запись нельзя перезаписать этой операцией
- **AND** валидатор и рендерер применяют одинаковые правила для пробельных, слишком длинных и пустых после нормализации slug

#### Scenario: Author revises an existing legacy routing Skill

- **WHEN** администратор показывает правку опубликованного профиля со старым именем
- **THEN** предпросмотр показывает каноническое имя YAML и карточки, где она применима
- **AND** запись сохраняет фактический ID отдельного Skill или путь общего профиля и существующие ссылки реестра
- **AND** при совпадении с уже принятым уникальным каноническим именем оно сохраняется

### Requirement: Preview the exact routing publication

Помощник SHALL предоставлять предпросмотр изменений в Markdown и записи общего `agents.json` по указанному Model ID и версии. Предпросмотр и публикация SHALL строить один и тот же результат для одинаковых полей и версии.

#### Scenario: Author previews an update

- **WHEN** автор передаёт черновик для существующего маршрута
- **THEN** предпросмотр выводит добавления, удаления и изменения в профиле и записи, показывает путь и версию
- **AND** операция не создаёт версию Skill и не меняет его содержимое
- **AND** одноимённые или соседние записи не включаются в запись исправления

#### Scenario: Another administrator updates the catalog after preview

- **WHEN** сохранение передаёт версию, которая перестала быть текущей
- **THEN** сохранение отклоняется без частичной записи
- **AND** помощник перечитывает каталог, повторяет ревью и строит новый предпросмотр существенных изменений для согласования

### Requirement: Create revise and review in one authoring workflow

Административный комплект SHALL предоставлять один системный промпт и рабочие Skills для создания, обновления, ревью и диагностики. Для существующего профиля автор SHALL использовать опубликованный текст как исходную версию. При явно выбранной группе ревью SHALL обозначать её состав и покрытие.

#### Scenario: Administrator requests a narrow routing fix

- **WHEN** пользователь просит исправить конкретный пограничный запрос
- **THEN** агент предлагает правку с сохранением применимых границ, показывает diff и полный текст предложенных позитивных и негативных примеров
- **AND** указывает, какие соседние профили были проверены, и показывает исходный запрос как кейс для повторной проверки
- **AND** при порученной публикации сохраняет согласованные изменения штатной версионируемой операцией
