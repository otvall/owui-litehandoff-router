# Spec Delta

## Purpose

Предоставлять терминальные команды только выбранным сабагентам через их серверную конфигурацию, сохраняя штатные подключения OWUI, пользователя исполнения и границы возможностей моделей.

## ADDED Requirements

### Requirement: Terminal access is an explicit optional agent binding

Система SHALL включать терминал только агенту с явно заданной серверной привязкой к одному подключению OWUI. Отсутствующая или пустая привязка SHALL означать отсутствие терминала. Публичный Router SHALL оставаться без терминала. Один лишь штатный флаг capability Terminal SHALL NOT создавать привязку.

#### Scenario: Only selected agents have a terminal

- **WHEN** A привязан к терминалу T, а B и C не имеют привязки
- **THEN** A получает терминальные Tools T, а B, C и Router их не получают
- **AND** настройка терминала для B и C не требуется

#### Scenario: Existing models have no new configuration

- **WHEN** установлен обновлённый комплект, но привязки ни у одного агента не заданы
- **THEN** их существующие Tools, MCP и Skills продолжают работать без терминала

#### Scenario: Native terminal capability conflicts with a binding

- **WHEN** у A задана непустая привязка, но capability Terminal явно выключен
- **THEN** подготовка A возвращает понятную ошибку конфигурации до генерации
- **AND** система не включает терминал в обход запрета и не игнорирует обязательную привязку

### Requirement: Terminal selection comes only from trusted model configuration

Система SHALL разрешать привязку только к уже настроенному серверному подключению терминала OWUI. Клиентские параметры, переключатели, аргументы делегирования, история и родительский чат SHALL NOT выбирать или менять терминал агента. URL и персональные браузерные терминалы SHALL NOT заменять серверную привязку.

#### Scenario: Parent and destination select different terminals

- **WHEN** в родительском запросе выбран T1, а серверная конфигурация A указывает T2
- **THEN** A использует только T2
- **AND** Router и агент без привязки не получают T1

#### Scenario: Assignment attempts to select a terminal

- **WHEN** аргументы параллельного задания содержат дополнительный terminal ID или URL
- **THEN** задание отклоняется по действующему правилу допустимых аргументов до dispatch
- **AND** содержимое пользовательского текста само по себе не меняет серверную привязку

### Requirement: Bound agents execute server terminal tools through the native loop

Агент с допустимой привязкой SHALL выполнять серверные терминальные Tools и получать инструкции сервера при обычном handoff, параллельной работе и финальном handoff через штатный Tool loop. Продолжения SHALL сохранять его привязку без накопления инструкций. Управление интерактивной панелью пользователя и автоматическое подключение терминальных Skills/AGENTS.md SHALL NOT добавляться.

#### Scenario: Handoff executes a command and reads its result

- **WHEN** A получает handoff и вызывает доступную на T команду, затем читает созданный ею тестовый файл
- **THEN** оба вызова действительно исполняются на T
- **AND** последующая генерация A получает результаты и сохраняет собственные настройки модели

#### Scenario: Mixed parallel group leads to a final agent

- **WHEN** A с терминалом и B без терминала успешно выполняют параллельные задания, после чего выбран C с собственной привязкой
- **THEN** A выполняет терминальные Tools в дочернем чате, B работает только со своими ресурсами, а C использует свою привязку в основном чате
- **AND** дочернему агенту не требуется открытая терминальная панель браузера

### Requirement: Terminal capabilities do not survive a model switch

При подготовке модели система SHALL заменять действующие терминальные Tools, привязку и добавленные серверные инструкции набором выбранной модели. Ресурсы и управляемые инструкции предыдущего агента SHALL NOT становиться возможностями следующего агента или Router. История SHALL NOT повторно исполнять завершённые команды.

#### Scenario: A terminal agent is followed by an agent without a terminal

- **WHEN** после A с T выбран B без привязки либо начался новый цикл Router
- **THEN** действующие Tools, терминальная привязка и добавленные системные инструкции T отсутствуют
- **AND** сохранённый результат A может использоваться как справочные данные без восстановления его callable

#### Scenario: Workers use identically named operations

- **WHEN** A с T1 и B с T2 одновременно вызывают `run_command`
- **THEN** каждый вызов направляется только в подключение своего агента с контекстом своего дочернего чата
- **AND** callable, авторизация и результаты другого работника не подставляются

### Requirement: Existing terminal session policy is preserved

Система SHALL использовать штатные настройки сессий и контекстов выбранного подключения OWUI с фактическим chat ID исполнителя. Она SHALL NOT создавать отдельные среды, менять политику хранения или объявлять разделение chat ID изоляцией файловой системы. Несколько выбранных агентов SHALL иметь возможность ссылаться на одно подключение.

#### Scenario: Parallel assignments use child chat context

- **WHEN** два задания A используют одно подключение с политикой контекста по chat ID
- **THEN** терминальные запросы используют разные фактические дочерние chat IDs
- **AND** обычный или финальный handoff использует chat ID основного чата

#### Scenario: Connection uses a shared backend

- **WHEN** подключение настроено на общую среду без отдельных контекстов
- **THEN** Router сохраняет это поведение без создания контейнеров или очистки общей файловой системы
- **AND** документация явно отличает изоляцию возможностей моделей от изоляции среды терминала

### Requirement: Terminal binding is revalidated before execution

Перед вызовом терминального Tool система SHALL повторно проверить доступ пользователя к модели, её владельца, актуальную привязку, право владельца на подключение и действующие запреты подключения. Устаревший callable SHALL NOT выполнять команду после отзыва привязки, смены владельца или запрета ресурса, включая native refresh.

#### Scenario: Prepared callable outlives its binding

- **WHEN** после подготовки A привязку T удалили или заменили на T2, а модель вызывает прежний Tool
- **THEN** вызов завершается ошибкой до обращения к T
- **AND** старый callable не переключается молча на T2

#### Scenario: Owner or connection access changes

- **WHEN** после подготовки изменился владелец модели, отозван его доступ к T либо T выключен
- **THEN** следующий терминальный вызов отклоняется
- **AND** native refresh не снимает проверку

### Requirement: Cancellation stops further terminal dispatch without replay

При Stop, отмене или deadline система SHALL отменять своё ожидание терминального вызова и прекращать новые команды отменённой задачи. Поздний результат SHALL NOT возобновлять группу или запускать финального агента. Уже переданные backend команды SHALL NOT повторяться или объявляться отменёнными задним числом; завершение удалённого процесса определяется штатным backend.

#### Scenario: Stop occurs during a terminal command

- **WHEN** пользователь останавливает группу во время ожидания ответа T
- **THEN** незавершённая задача и её локальное ожидание прекращаются, новые терминальные вызовы не отправляются
- **AND** общий терминальный сервер не выключается, команда не повторяется и C не запускается

#### Scenario: Backend replies after a deadline

- **WHEN** ответ терминала приходит после истечения срока группы
- **THEN** он не превращает исход timeout в успех и не возобновляет Router
