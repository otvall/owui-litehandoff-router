# Proposal

## Why

Некоторым сабагентам нужен терминал для выполнения команд и работы с файлами, тогда как остальным достаточно их Tools и Skills. Текущий Router собирает возможности модели заново и не подключает штатные терминальные Tools OWUI, поэтому одного переключателя Terminal в карточке агента недостаточно.

## What Changes

- Добавить необязательную серверную привязку Workspace Model агента к одному уже настроенному терминальному подключению OWUI. По умолчанию терминал отсутствует; привязка задаётся только выбранным агентам.
- Автоматически предоставлять выбранному агенту серверные терминальные Tools при обычном handoff, параллельном задании и финальном handoff, включая продолжения после Tool calls.
- Сохранить разделение права владельца модели на подключение и личности пользователя исполнения: не выдавать пользователю прямой доступ к терминалу и не использовать токены владельца вместо пользовательских.
- Исключить наследование терминала из родительского чата, другого агента, клиентских параметров или истории. Публичный Router остаётся без терминала.
- Сохранять штатные настройки подключения, маршрутизацию сессий и контекстов OWUI. Не создавать рабочие среды, контейнеры или отдельный сервис и не обещать изоляцию файловой системы поверх настроек терминального backend.
- Документировать настройку, ограничения и проверку на OWUI 0.12.3 с двумя самостоятельными Functions. Управление интерактивной панелью терминала пользователя, автоматический импорт терминальных Skills/AGENTS.md и новый перенос терминальных файлов между агентами в этот change не входят.

## Capabilities

### New Capabilities

- `agent-terminal-access`: выборочная привязка агента к серверному терминалу, исполнение его Tools, границы контекста, сессии, ошибки и остановка.

### Modified Capabilities

- `workspace-model-execution`: автоматическая подготовка необязательного терминала выбранной модели и сохранение атомарной подготовки при ошибках или конфликтующих inlet-фильтрах.
- `model-bound-resource-access`: распространение доступа через разрешённую модель на её настроенное терминальное подключение с сохранением пользователя исполнения и без прямых grants.

## Impact

Основные точки изменения: `model_execution.py`, `resources.py`, адаптация терминальных API OWUI в `owui_adapter.py` и небольшой модуль терминальных возможностей при необходимости. Параллельная ветка должна выбирать подключение по модели уже внутри дочернего контекста, без переноса `terminal_id` родителя в dispatch.

Потребуются проверки подготовки, native callable refresh, ACL и авторизации, настоящего Tool loop в обычном и дочернем чате, Stop/deadline и регрессий существующих Tools/MCP/Skills. Обновляются документация и оба standalone exports; схема БД, API аргументов `lite_delegate`/`lite_parallel` и зависимости проекта не меняются. Нужен заранее доступный сервер терминала в закрытом контуре. Реальная production-инсталляция в рамках исследования не проверялась.
