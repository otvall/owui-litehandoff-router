# Proposal

## Статус синхронизации 2026-11-05

Change завершён: 18/18 задач. Контракт Visualizer синхронизируется для единственного поддерживаемого релиза из `workspace-model-execution` — OWUI 0.12.5. Историческая HTTP/browser-приёмка выполнена на 0.12.3; её результаты сохранены в `docs/acceptance.md` и не объявляются повторной браузерной проверкой 0.12.5. Синхронизация не меняет установленный плагин и не добавляет поддержку прежнего OWUI.

## Why

При запуске агента с Inline Visualizer 2.1.1 через `lite_parallel` вызов визуализации может остаться в ожидании ответа браузера, открытого на основном чате, и не дойти до генерации содержимого. Нужно обеспечить и проверить завершение задания и отображение его интерактивной визуализации в собственном дочернем чате по ссылке «Открыть выполнение».

## What Changes

- Закрепить согласованные Tool/Skill Inline Visualizer 2.2.3 из проверенного upstream snapshot для единственного поддерживаемого релиза Open WebUI, заданного в `workspace-model-execution`. Версия 2.1.1 используется для воспроизведения прежнего зависания, её неизменённый код не входит в обещание совместимости.
- Добавить воспроизводимую проверку через настоящие установочные Filter/Pipe, native Tool loop и живую браузерную сессию: основной чат открыт, дочерний чат ещё не открыт, браузер не подтверждает его запрос определения языка, но Tool завершается и агент выдаёт HTML/SVG.
- Проверить отображение и интерактивность embed при открытии дочернего чата, во время доступного исполнения и после завершения/reload; два параллельных задания должны сохранять собственные визуализации.
- Сначала проверить штатный плагин 2.2.3 без изменений runtime. Если gate выявит оставшийся дефект интеграции, исправить только подтверждённую привязку событий/результата работника, сохранив native исполнение и идентичность дочернего чата.
- Обновить инструкции установки и отчёт приёмки: версии, настройки iframe, обновление установленного Tool/Skill, ограничения и проверенные способы просмотра.

Публикация embeds или потока HTML сабагента в основной чат, смена транспортной Router-модели, новый frontend и изменение протокола `lite_parallel` в этот change не входят.

## Capabilities

### New Capabilities

- `agent-task-visualizations`: завершение задания с поддерживаемым Inline Visualizer без обязательного браузерного подтверждения и просмотр принадлежащей заданию визуализации в его дочернем чате.

### Modified Capabilities

Нет. Новая capability дополняет основные контракты `parallel-agent-tasks`, `agent-task-inspection` и `model-bound-resource-access`, не заменяя их требования.

## Impact

- Проверки: отдельный сценарий совместимости рядом с `tools/parallel_acceptance.py` и детерминированным провайдером; точечные native/unit regression tests только при обнаруженном дефекте runtime.
- Возможные места исправления: передача событий в `model_execution.py`, загрузка и привязка Tools в `owui_adapter.py`/`binding.py`; конкретное изменение определяется воспроизведённым остаточным сбоем, а не предполагается заранее.
- Документация: `docs/setup.md`, `docs/compatibility.md`, `docs/acceptance.md`, `tools/README.md`.
- Inline Visualizer остаётся отдельным необязательным Workspace Tool и Skill. Комплект Router сохраняет две самостоятельные Functions, не требует патча OWUI, новой БД или нового сервиса. Upstream-файлы подготавливаются заранее для закрытого контура; production-установка пользователя этой приёмкой не изменяется.
