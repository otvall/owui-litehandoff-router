# Proposal

## Why

Полные результаты Tools, справочный обзор Router и видимая переписка накапливаются при каждом продолжении и могут переполнить окно модели. Нужны управляемое скрытие старых результатов, проверка бюджета и суммаризация без изменения исходной истории, повторного исполнения действий и смешивания контекста исполнителей.

## What Changes

- Очищать модельную историю обычного агента по подтверждённым границам handoff. Служебные реплики Router исключаются. Закрытые блоки Inline Visualizer в завершённых ответах других агентов заменяются заглушками по маркерам `@@@VIZ-START` и `@@@VIZ-END`. Остальные артефакты передаются в исходном виде по действующим правилам контекста. Дополнительные вызовы LLM не нужны.

- Добавить административное окно N самых свежих обычных Tool results в представлении каждого исполнителя, включая текущую цепочку. Более старые результаты заменяются текстовой плашкой только в контексте модели; интерфейс и оригиналы в чате не меняются.
- Применять одно окно к обычным рабочим результатам: у Router — к собственной истории и вложенным результатам исторических передач, у агента/работника — к допустимой собственной цепочке. `lite_delegate` не расходует N; текущие Skills, native-контекст и обязательный пакет группы сохраняются.
- В проекции Router представлять завершённый исторический handoff реальной парой `assistant.tool_calls(lite_delegate)` → отдельное сообщение `tool` с итогами агента в `tool_results`. Пара остаётся рядом с исходным вопросом, полный серверный маркер сохраняется.
- Для обычного handoff передавать агенту отфильтрованные завершённые ходы и применённую общую сводку в отдельном `user` с меткой `[Conversation history]` перед текущим вопросом. Сохранить отдельную текущую Tool-цепочку и существующий формат Router.
- Собирать собственный промпт и служебные правила Router, агента и параллельного работника в одно исходящее `system`-сообщение для каждого получателя. Оба XML-каталога Skills передавать отдельной актуальной служебной парой `list_available_skills` → `role=tool`, без дублирования в system. Разделить `routing_skills` и обычный `available_skills` в штатной структуре OWUI с дочерними полями; XML `id` отображает внутренний `skill_id`. Обычные Skills поступают из конфигурации/карточки и явного выбора в чате с actor-проверкой; routing-записи не дублируются. Сохранить актуальный scope; схемы вызываемых Tools оставить в API-поле `tools`, не дублируя вручную XML шаблона GLM.
- Проверять полный входной бюджет перед каждым вызовом Router, агента и работника с общим значением и переопределениями по Workspace Model ID. Учитывать инструкции, схемы Tools, историю и мультимодальный контекст; явно отличать оценку от точного подсчёта.
- Переиспользовать общую инкрементальную сводку завершённых ходов видимой переписки для Router и обычных агентов основного чата. Сохранять совместимость по покрытому префиксу ветки, используя действующую выделенную модель без Tools. Контекст и бюджет каждого получателя проверять отдельно.
- Сохранять полную серверную историю для handoff, provider-аудита и parallel state; эффективный контекст модели и `__messages__` её Tools должен совпадать.
- Возвращать явную ошибку, если обязательные данные не помещаются или допустимое сжатие не помогло. Добавить диагностику без содержимого сообщений. По умолчанию окно и summary выключены; новая структура сообщений/XML действует независимо от N. Штатная суммаризация OWUI остаётся выключенной.
- **BREAKING при включении политики:** старые результаты могут стать недоступны модели, а старые части переписки — заменяться обозначенным summary. Без включения настроек прежняя передача контекста сохраняется.
- Размер отдельного результата и чтение ранее выданных данных остаются ответственностью Tools. Общий retrieval Tool, обрезание отдельных результатов и UI-плашки не входят в change.

## Capabilities

### New Capabilities

- `context-budgeting`: административная политика окна результатов, бюджета всего запроса, суммаризации, checkpoints и отказа при невозможности подготовки.

### Modified Capabilities

- `conversation-context`: определить исторические пары делегирования, единую системную инструкцию и XML-каталог, разрешить ограниченные представления и позднее summary при сохранении полной истории и scope исполнителя.
- `parallel-agent-tasks`: согласовать ограничение модельного представления с полнотой сохранённых результатов группы и защитой полного пакета при финальном handoff.

## Impact

Затрагиваются `history.py`, `skills.py`, `model_execution.py`, `runtime.py`, `entrypoints/router_preparation.py`, `parallel.py`, `owui_adapter.py`, модули политики/checkpoints, обе standalone Functions и документация. Административные настройки не принимаются из клиентского metadata. Общая сводка хранится в существующем `chat.meta.lite_shared_summaries`. Работники получают отдельные поручения. Суммаризация текущих раундов Tools и отдельные сводки исполнителей находятся вне объёма изменения. Требуются unit/native/HTTP проверки OWUI 0.13.3 и отдельная смысловая приёмка GLM-5.3-Flash. Task-only и native-scope гарантии прежних changes сохраняются.

## Delivery State

Ветка `feat/tool-history-context-limits` перенесена непосредственно на `main` (`3d684db`), без коммита папочных routing Skills. Рабочий scope — текст/HTML; формат `skill_path` прежней ветки не становится новой зависимостью. Установленные пользовательские вложения сохраняются; отдельная политика неоднозначных изображений Tool results не входит в текущий этап.

Реализованы окно N, исторические пакеты Router, отдельный XML-каталог, формат агента и общая сводка. Предзапросная проверка использует бюджет адресата и расширяет совместимую общую сводку при необходимости. Без настроенного бюджета действуют прежние триггеры по `prompt_tokens` и переполнению провайдера.

Приёмка финальной сборки включает 165 модульных, 82 нативных и 22 HTTP-проверки, а также пять сквозных сценариев на GLM-5.3-Flash. Результаты и ограничения оценки входа описаны в задачах и настройках.
