# Spec Delta

## MODIFIED Requirements

### Requirement: Resource owners and permissions are checked afresh

Владелец и ресурсы SHALL определяться по актуальной серверной конфигурации и проверяться при подготовке и применимых вызовах. Отсутствующий владелец, удалённый или запрещённый ему обязательный ресурс SHALL приводить к явной ошибке без частично подготовленной генерации. Подстановка другого владельца или администратора SHALL NOT выполняться.

#### Scenario: Owner cannot load a required resource

- **WHEN** обязательный Tool, Skill или MCP-подключение недоступны владельцу выбранной модели
- **THEN** агент не начинает генерацию с неполным набором
- **AND** ошибка не обходится правами пользователя, другого владельца или администратора

#### Scenario: Owner changes or access is revoked

- **WHEN** между подготовками изменился владелец модели, её attachments или права на обязательный ресурс
- **THEN** следующая подготовка использует актуальную конфигурацию и права
- **AND** старый callable или результат не восстанавливает утраченную возможность

#### Scenario: Routing skill is unavailable to its authority

- **WHEN** routing Skill отсутствует, неактивен или недоступен владельцу Router
- **THEN** соответствующий агент исключается из персонального реестра с диагностикой
- **AND** отсутствие прямого read-grant пользователя само по себе не считается такой ошибкой

#### Scenario: MCP function filter changes before continuation

- **WHEN** MCP-сервер предоставляет `lookup` и `other`, а администратор между подготовками одного запроса меняет `function_name_filter_list` с `lookup` на `other`
- **THEN** следующая подготовка публикует разрешённый `other` и исключает запрещённый `lookup`
- **AND** открытое соединение не закрепляет прежний разрешённый набор
- **AND** пустой после фильтрации набор обязательного подключения вызывает явную ошибку подготовки

#### Scenario: A prepared MCP callable loses function permission

- **WHEN** после подготовки MCP-функции администратор исключает её из `function_name_filter_list`, а затем вызывается сохранённый callable
- **THEN** вызов отклоняется до отправки операции MCP-серверу
- **AND** проверка доступа владельца к самому подключению не заменяет проверку допустимости функции
- **AND** разрешённые вызовы сохраняют пользователя исполнения и его авторизацию

#### Scenario: MCP filter changes preserve native matching rules

- **WHEN** администратор меняет допустимый серверный фильтр в строковом формате или формате списка, включая штатные шаблоны
- **THEN** публикация и последующие вызовы применяют одинаковые правила сопоставления Open WebUI 0.12.5
- **AND** отсутствие ограничивающего фильтра не превращается в запрет всех функций

## ADDED Requirements

### Requirement: MCP sessions end with their owning request

При окончательном завершении запроса система SHALL освобождать принадлежащие ему локальные MCP-задачи и соединения в пределах 5 секунд, включая Stop, отмену и ошибку. Зависшая операция SHALL NOT блокировать локальное закрытие. Закрытие SHALL быть идемпотентным; ожидающие вызовы SHALL завершаться результатом, ошибкой или отменой и SHALL NOT запускаться повторно автоматически.

#### Scenario: Stop interrupts a hanging MCP call

- **WHEN** обычный запрос Router или handoff-агента остановлен во время MCP-вызова, который не возвращает ответ
- **THEN** штатное завершение запроса запускает локальное закрытие без ручного действия пользователя или теста
- **AND** принадлежащие запросу MCP-задачи и соединения завершаются в пределах бюджета закрытия
- **AND** активный и ожидающие вызовы не остаются в бессрочном ожидании
- **AND** новые операции, скрытый повтор и продолжение генерации после Stop не запускаются

#### Scenario: Cancellation arrives during the permission check

- **WHEN** вызов отменяется во время асинхронной проверки серверной политики перед отправкой операции
- **THEN** после проверки отменённый вызов не отправляется в MCP transport
- **AND** это правило действует, пока владелец запроса ещё завершает свой `finally`

#### Scenario: Completion and failure release request sessions

- **WHEN** запрос окончательно завершается успехом либо ошибкой подготовки, провайдера или чтения потока
- **THEN** все созданные им MCP-сессии проходят тот же механизм локального закрытия
- **AND** повторный cleanup не закрывает ресурсы другого запроса и не скрывает исходную ошибку

#### Scenario: Tool continuations keep a live request session

- **WHEN** одно пользовательское сообщение проходит несколько генераций и MCP-вызовов в штатном Tool loop
- **THEN** промежуточный возврат Pipe или окончание отдельного provider stream не закрывает сессию продолжающегося запроса
- **AND** последующие допустимые вызовы используют пригодную сессию своего пользователя и модели

#### Scenario: Request ends while MCP connection is opening

- **WHEN** отмена запроса происходит до завершения открытия MCP-подключения
- **THEN** локальная попытка подключения и созданные ею ресурсы завершаются в пределах бюджета закрытия
- **AND** общий бюджет включает отмену открытия, ожидание SDK cancellation и disconnect без отдельных последовательных таймаутов
- **AND** ожидающая подготовка получает отмену или ошибку и не публикует частичный набор Tools

#### Scenario: Parallel cleanup remains isolated and repeatable

- **WHEN** Stop или deadline параллельной группы и окончание её дочернего запроса одновременно закрывают одну MCP-сессию
- **THEN** повторное закрытие безопасно и завершает ожидающие вызовы
- **AND** MCP-сессии других работников и пользователей остаются независимыми
- **AND** закрытие локального соединения не считается доказательством отката удалённой операции
