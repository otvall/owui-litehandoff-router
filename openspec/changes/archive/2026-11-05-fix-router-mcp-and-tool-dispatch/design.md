# Design

## Context

Мотивация и объём находятся в `proposal.md`, контракты — в двух delta specs. Целевая среда — только **Open WebUI 0.12.5**. Основная `workspace-model-execution` уже содержит это ограничение; новый change уточняет сценарии проверки и не повторяет миграцию версий.

Исследован текущий checkout с незакоммиченным переходом на 0.12.5 и неизменённые исходники установленного wheel 0.12.5. Наблюдения ревью:

| Дефект | Текущий путь | Подтверждение до исправления |
| --- | --- | --- |
| P1: MCP после Stop | `McpSession.__init__` регистрирует callback владельца, `stop()` ставит sentinel за активным `client.call_tool()` | После отмены владельца: `request_done=True`, `session_done=False`, `disconnected=False`, в очереди остаётся sentinel |
| P2: OpenAPI collision | `OWUIAdapter.tools` меняет ключ реестра серверного Tool, но не `spec.name`; локальная ветка обновляет оба | Два сервера дают пары ключ/имя схемы `lookup/lookup` и `server_openapi_b_lookup/lookup` |
| P2: stale MCP filter | `connect_mcp` фильтрует specs один раз, `load_capabilities` повторно берёт `session.ready`, invoker проверяет только подключение | После `lookup` → `other` повторная подготовка всё ещё публикует `lookup`; прежний callable выполняет его |

Точечные воспроизведения использовали настоящий код роутера; проверка фильтра — native Config 0.12.5 и заменённый сетевой клиент, проверка Stop — управляемый зависший клиент без сети. Это доказательство дефектов, а не выполненная приёмка исправлений. Нынешний native Stop-тест явно вызывает `session.close()`, поэтому не проверяет автоматическую финализацию запроса.

`Filter.inlet` создаёт доверенные данные в ASGI scope и общий `metadata.tools` до поверхностного копирования metadata внутри OWUI. `Pipe.pipe` готовит очередную генерацию и публикует её набор в тот же словарь. Сессии разделяются по actor, owner, модели и server ID. В `parallel.py` уже есть явный cleanup дочерних задач. Эти границы сохраняются.

## Goals / Non-Goals

**Goals:**

- Свести автоматическое завершение MCP и существующие явные cleanup-пути к одной идемпотентной операции без ожидания зависшей бизнес-операции.
- Отделить допустимое публичное имя Tool от исходного имени операции, сохраняя между ними проверяемую связь.
- Отделить время жизни транспорта MCP от актуальности серверной политики функций.
- Проверять исправления через реальные entrypoints и native API 0.12.5, сохраняя атомарную публикацию и owner/actor authority.

**Non-Goals:**

- Объединение Filter и Pipe, изменение протокола handoff, удаление `phase` или сокращение receipt.
- Новый transport, scheduler, глобальный пул MCP-сессий, новая Valve таймаута либо поддержка других релизов OWUI.
- Обещание отмены удалённого побочного действия после закрытия локального соединения.

## Decisions

### 1. Одна операция завершения сессии, вызываемая жизненным циклом запроса

Сохранить request-local управление сессиями и привязку к владельцу полного native запроса. Завершение этого владельца должно немедленно запрещать новые команды и прерывать активное ожидание; sentinel, требующий сначала дождаться `call_tool`, для этого недостаточен. Тот же механизм вызывается при ошибке подготовки, явном закрытии и cleanup работника. Повторные вызовы сходятся к одной задаче закрытия.

Активное ожидание и queued futures нужно учитывать явно: после остановки каждый получает результат, ошибку закрытия или отмену. Внутренняя отмена не должна оставлять активный future незавершённым или подавлять исходную ошибку запроса. `finally` сессии освобождает native клиент; все выходы, включая отмену до готовности подключения, проходят этот путь.

Для локального закрытия использовать общий бюджет **5 секунд**, основанный на существующем `McpSession.close()`, без новой настройки. Несколько соединений одного запроса закрываются с общим deadline, а не последовательными бюджетами по 5 секунд на каждое. Ошибка закрытия диагностируется; она не превращает исходную операцию в успешную и не запускает повтор. Контрольный тест проверяет как отсутствие живой session task, так и закрытие native клиента/транспорта и завершение ожидающих вызовов.

Клиент передаётся во владение `McpSession` сразу после создания, до `connect()` и `list_tool_specs()`. Отдельная задача завершения наблюдает за последовательным работником и сигналом остановки. При первой остановке фиксируется абсолютный deadline; отмена работника и штатный disconnect выполняются параллельно, а оставшийся бюджет ограничивает их совместное ожидание. Это включает shielded courtesy-cancel MCP SDK и cleanup незавершённого открытия; повторный close не обновляет deadline. После асинхронной проверки политики работник ещё раз проверяет отмену future и остановку сессии перед отправкой операции.

В OWUI 0.12.5 `MCPClient` сам создаёт `session_task`, а `disconnect()` отменяет и ожидает её. Использовать этот штатный lifecycle через `owui_adapter.py`; не восстанавливать ограничения SDK 1.x как причину нового слоя совместимости. Существующую очередь допустимо сохранить для текущего порядка вызовов, но её остановка должна прерывать зависший вызов. Полная замена очереди не нужна для данного исправления.

Не закрывать MCP в безусловном `finally` каждого вызова Pipe или каждого provider stream: это промежуточные этапы одного native Tool loop. Обязателен интеграционный контроль, в котором несколько продолжений используют пригодную сессию, а окончательный выход/ошибка/Stop закрывает её автоматически. Ручной `close()` допускается в аварийном teardown теста только после фиксации провалившегося критерия.

Отклонены: только sentinel в очереди; только ручное закрытие в тестах; закрытие на каждом возврате Pipe; ожидание сетевого timeout бизнес-операции вместо ограниченного локального cleanup.

### 2. Регистрация Tool обновляет имя схемы вместе с ключом реестра

Сохранить существующее разрешение коллизий с переименованием серверного Tool. Выбранное публичное имя должно одновременно становиться ключом registry и именем копии его schema. Callable сохраняет привязку к исходному server ID и исходному имени операции: alias модели не отправляется внешнему серверу вместо operation name.

Публичное имя ограничить 64 символами: длинное имя сокращается с хешем полного кандидата, после чего проверяется коллизия уже опубликованного alias. При повторной коллизии формируется следующий кандидат, без потери Tools и без изменения исходной серверной операции. Общий helper сохраняет прежнюю схему сокращения MCP; короткие имена и прежние допустимые alias остаются прежними.

Локальную и OpenAPI-ветки следует свести к небольшому общему шагу регистрации, если это убирает расхождение без изменения их правил загрузки и authority. Независимо от формы helper, перед публикацией проверять инвариант: имена уникальны и у каждого ключа имя schema совпадает с ним. Зарезервированные routing/Skill/terminal имена и прежние ошибки атомарной подготовки сохраняются.

Проверки должны вызывать подготовленные функции по опубликованным именам и наблюдать конкретный ресурс назначения. Одного сравнения строк схем недостаточно. Нужны local/OpenAPI и OpenAPI/OpenAPI коллизии, оба порядка подключения серверов и обычный случай без коллизий.

Отклонены: молчаливое удаление второго инструмента; изменение только ключа; передача публичного alias вместо исходной операции; изменение схем общего native кэша in-place.

### 3. Кэшировать транспорт и исходные MCP specs отдельно от разрешённого набора

Сохранять пригодное соединение по прежнему ключу actor/owner/model/server. Не использовать первоначально отфильтрованный результат `session.ready` как постоянное разрешение функций. Сессионный слой хранит исходные specs полученного каталога; их фильтрация для публикации выполняется по текущей серверной конфигурации при каждой подготовке. Это позволяет не только убрать `lookup`, но и опубликовать уже предоставляемый сервером `other` после изменения фильтра без переподключения.

В адаптере выделить общий путь чтения текущего подключения, проверки глобального enable/owner ACL и допустимости функции через штатный `is_string_allowed`. Путь используется и для формирования видимых specs, и непосредственно перед `call_tool` сохранённого callable. Поддержать нативные строковый/list форматы и шаблоны без собственного языка фильтров. Пустой фильтр сохраняет нативный смысл; отсутствие разрешённых функций у обязательного подключения остаётся ошибкой подготовки.

Сырые specs никогда не публикуются в LLM до проверки политики. Перенос фильтрации из подключения в этот общий путь меняет только внутренний контракт адаптера/сессии; проверки внешнего разрешённого набора сохраняются на уровне `load_capabilities` и исполняемого callable. Owner ACL, актуальные model attachments и пользовательская авторизация остаются независимыми проверками. Проверка перед отправкой не обещает отозвать операцию, уже отправленную до изменения фильтра.

Отклонены: переподключение на каждом вызове только ради перечитывания локального фильтра; проверка только при генерации схем; повторная фильтрация уже урезанного каталога, из которого невозможно восстановить разрешённый `other`.

### 4. Единственный релиз и две Functions остаются контрактом

Сохранить `OWUI_VERSION = "0.12.5"`, соответствующие зависимости, заголовки exports и проверку package metadata / `open_webui.env.VERSION`. Delta `Single supported release` явно называет 0.12.5 текущей целевой версией и сохраняет существующий сценарий отказа других релизов. В этой задаче требуется регрессия этого контракта, а не восстановление version profiles.

Все OWUI imports остаются в адаптере. Builder собирает согласованную пару из исходников; прямые исправления generated `dist/` не являются реализацией. Изменение общих helpers проверяется и в холодном standalone импорте обоих файлов, и в native цепочке.

## Risks / Trade-offs

- [Очистка на промежуточной генерации оборвёт исправный Tool loop] → привязка к полному native запросу и тест нескольких продолжений без ручного закрытия.
- [Отмена закрытия оставит futures или соединения живыми] → один владелец cleanup, общий deadline, тесты active/queued/opening и повторного закрытия, наблюдение native disconnect.
- [Повторный cleanup родителей и работников даст гонку] → идемпотентное закрытие и отдельные проверки параллельной отмены/изоляции.
- [Политика перед вызовом добавляет чтение конфигурации] → кэшировать транспорт и каталог, но не разрешение функции; не открывать новую сессию ради локальной проверки.
- [Переименование потеряет исходный ресурс или авторизацию] → тестировать настоящий callable dispatch и исходный operation name, не только схему.
- [Исторический `add-owui-0111-router` противоречит целевой версии] → этот change и текущая основная спека используют только 0.12.5; старые артефакты не являются планом возврата legacy-поддержки и не переписываются здесь.

## Migration Plan

1. Реализовать три исправления в исходниках, начиная с падающих воспроизведений; выполнить unit/native regression на неизменённом OWUI 0.12.5 и отдельной БД.
2. Собрать обе Functions и подтвердить cold import, native ordinary handoff и сценарии отмены/коллизий/смены фильтра через актуальные exports. Доказательства разделяют настоящий MCP transport и заменённый транспорт генерации.
3. Для установки сохранить текущие согласованные Functions, `AGENTS` и Valves, остановить активные запросы и обновить оба файла с восстановлением конфигурации. Рабочая установка не изменяется автоматически в рамках реализации.
4. Для rollback восстановить согласованную пару для OWUI 0.12.5 и её настройки. Новых БД, grants и миграций данных нет; общие серверы и файлы не удаляются.
