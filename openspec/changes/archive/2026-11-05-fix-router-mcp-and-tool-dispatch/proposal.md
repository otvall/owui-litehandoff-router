# Proposal

## Why

Ревью текущих Router и Filter для OWUI 0.12.5 подтвердило три дефекта: зависшая MCP-сессия остаётся открытой после Stop, коллизия имён OpenAPI Tools нарушает соответствие схемы и callable, а изменение серверного MCP-фильтра не отзывает ранее опубликованную функцию. Нужен отдельный change с исправлениями и регрессионными проверками на единственной актуальной целевой версии **Open WebUI 0.12.5**.

## What Changes

- **P1 — MCP lifecycle:** гарантировать ограниченное по времени завершение принадлежащих запросу MCP-задач и соединений при Stop, отмене, ошибке и окончательном завершении запроса. Промежуточные Tool-продолжения сохраняют пригодную сессию; зависший вызов не блокирует её закрытие и не оставляет ожидающие вызовы незавершёнными.
- **P2 — OpenAPI dispatch:** синхронизировать опубликованное имя схемы, ключ реестра и callable при коллизиях local/OpenAPI и OpenAPI/OpenAPI Tools. Переименование не меняет исходную операцию внешнего сервера и не направляет вызов в другой ресурс.
- **P2 — MCP filters:** применять актуальный `function_name_filter_list` при повторной подготовке и перед каждым вызовом. Открытая сессия и старый callable не сохраняют функцию, которую серверная конфигурация уже запретила.
- Закрепить в delta spec текущую целевую и единственную поддерживаемую версию **0.12.5**, точную проверку версии в обеих Functions и отсутствие release profiles/legacy-комплектов. Это сохраняет уже записанный в основной спеке контракт, а не добавляет поддержку ещё одной версии.
- Дополнить unit/native проверки тремя воспроизведениями из ревью и пересобрать два standalone exports после реализации исправлений.

## Capabilities

### New Capabilities

Нет: исправления уточняют существующие контракты исполнения и доступа к ресурсам.

### Modified Capabilities

- `workspace-model-execution`: однозначное соответствие опубликованных Tools исполняемому реестру и явный целевой релиз OWUI 0.12.5.
- `model-bound-resource-access`: завершение MCP-сессий вместе с запросом и применение актуальных серверных фильтров к опубликованным и сохранённым callable.

## Impact

Основные места исправлений: `src/lite_handoff_router/capabilities.py`, `owui_adapter.py` и интеграция жизненного цикла в `entrypoints/lite_handoff_router.py`/`observation.py` при необходимости. Существующий явный cleanup дочерних задач в `parallel.py` должен остаться совместимым и идемпотентным. Filter продолжает создавать доверенное состояние запроса и общий Tool registry до native цикла; Pipe публикует подготовленный набор в тот же registry.

Регрессионные проверки затронут `tests/test_capabilities.py`, native MCP/resource contracts и standalone exports. Используются неизменённый OWUI 0.12.5 и его MCP SDK 2.x, изолированная тестовая БД и loopback MCP transport. Текущие 62 unit/export и 41 native test сами по себе не подтверждают исправление найденных случаев: Stop-тест вручную вызывает `session.close()`, а коллизии и изменение фильтра между продолжениями не покрыты.

Изменение не требует новой БД, дополнительных runtime-зависимостей, отдельного сервиса или патча OWUI. Оно не возвращает 0.11.1/0.12.3, не меняет аргументы `lite_delegate`/`lite_parallel`, owner/actor ACL и не обещает откат уже отправленной удалённой операции. Удаление `phase`, сокращение receipt и прочие необязательные архитектурные улучшения не входят в эту задачу исправления багов.
